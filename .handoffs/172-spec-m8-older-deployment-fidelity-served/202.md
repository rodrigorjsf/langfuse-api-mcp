# Handoff — #202: The request body schema of a write operation is the deployment's version's, not the newest release's

Status: DONE

## What was built
- The catalog generator keeps every distinct request body the release specs gave a write operation, each with the releases it holds for (`x-request-bodies` with `x-spans`). A body that comes back is stored once with both spans; bodies that differ only in `description`/`title` text are one body with the newest text.
- `catalog.Resolve` picks one body per write operation for the detected version, by the served-parameters rule (newest release not newer than the deployment; newest when undetected). `describe_operation` returns it, `execute_write` checks against it, in full at every cap.
- On 3.30.0 `scores_create` is described and checked with `traceId` required and no `sessionId`/`datasetRunId`; on 3.80.0 `models_create` without `unit` (or with `"unit": null`) is sent; on 4.46.0 it is refused before any request.
- The embedded catalog is regenerated from the same 403 releases / 118 specs: 504,215 -> 955,700 bytes. Nothing outside body data changed (recorded in the ADR-0012 amendment).
- Startup stops if a resolved body schema does not compile (`Catalog.BodyError`, checked in `cmd/langfuse-mcp`); schemas are compiled once, when a resolution first chooses them.

## Decisions & deviations
- **Data shape.** Union file has `x-request-bodies` (list; each `required`, `content`, `x-spans`) instead of `requestBody`; a plain OpenAPI `requestBody` still loads (holds for every release). Spans are runs of releases; the last body stays open-ended even when the operation left the spec (otherwise an undetected version would get an operation and no body).
- **Excluded operations** (ADR-0004, 17 IDs, 14 with a body) keep the newest body only (`x-newest-body-only`, no spans): full history would be 2,072,165 bytes (+311%), with the rule 955,700 (+89.5%, still over the ticket's +50%, rule applied as the ticket asks). Generator list `NEWEST_BODY_ONLY` duplicates Go `excluded`; load fails if an operation the server offers is marked. The reverse direction (an excluded op not trimmed) only costs size and is not tested.
- **`example` -> `examples: [value]`** added to `to_2020_12`: the first releases' `POST /ingestion`, `POST /scores` (280 releases each) and three `unstable/` operations (23) carry it. No body dropped.
- **Lazy compile** (`sync.Once` per stored body) so that `Load` does not compile 76 bodies where 34 are offered (#201). `Resolve` compiles the bodies of the resolved version; `Catalog.BodyError()` reports a failure; `cmd/langfuse-mcp` stops startup on it; `CheckBody` refuses every body for a non-compiled schema (`ErrInvalidBody`). Cleaning of hidden characters is still eager at load, for every stored body.
- **Body guidance release table removed** (`scoreTargets` is now a plain list): the resolved schema is the deployment's, and the #192 tests pass unedited. `Operation.deployment` is still used by the served-parameter messages.
- **Catalog tests share one loaded catalog** (`mustLoad` -> `sync.OnceValues`), as the server tests do since #201: each fresh `Load` + `Resolve` would otherwise compile the same bodies again (race run of `internal/catalog` 12.6 s at base, 42 s without this, 4.5 s with it).
- **Permanent hash pins dropped on review.** I first pinned SHA-256 of the 34 newest bodies and exact body counts; the Standards reviewer showed a weekly regeneration would break them with an opaque diff. Replaced by floors and by the one-off recorded comparison (ADR-0012 amendment, Reproduction).
- The v3.28.2 release spec is non-monotonic: its `models_create`/`prompts_create` bodies are the 3.0.0 ones, so a 3.28.2 deployment is checked against them (release spec is the authority; documented in tools.md).
- Size budget test (1 MiB) still passes at 0.91 MiB; a further growth of the catalog needs a look.

## Learnings
- The Bash tool expands a backslash-u escape in a quoted heredoc into the real character; gosec G116/staticcheck ST1018 then fail. Patch with Python writing `chr(92)` + `u...`, and `grep -nP '[^\x00-\x7F]'` afterwards (same as #178, #192).
- The shell is fish: `( cmd ) > log &` runs the command substitution in the foreground; use `bash -c` or `run_in_background`.
- Do not `git stash` + `git checkout <sha> -- files` to compare with the base: use `git archive <sha> | tar -x -C <scratch>` and run the base code there.
- A fresh `catalog.Load()` per test is now costly under `-race` because `Resolve` compiles the chosen bodies; share one catalog (`sync.OnceValues`).
