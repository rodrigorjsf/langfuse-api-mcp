## What was built
- If a config-file key is not a known setting (for example `LANGFUSE_CA_CRT`), startup logs one `WARN` line: `config file key ignored: not a known setting`, with the fields `file`, `line` and `key`. The value is never logged. Startup still succeeds.
- Known keys draw no warning. They are the CA variables, the 5 ambient variables, `LANGFUSE_BASE_URL`/`LANGFUSE_HOST`, and the keys documented as Planned: `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `LANGFUSE_MCP_ALLOW_WRITES`, `LANGFUSE_MCP_TRANSPORT`.
- In the key name, control, zero-width, bidi and tag characters are escaped as Go string-literal escapes. Names longer than 64 runes are cut and marked with `...`.
- The refusal of the Langfuse keys (`LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY`) is unchanged.

## Seams & tests
source: spec. The tests run at two seams:

## Decisions & deviations
- Interface change: `config.Load` now returns `(Config, []IgnoredKey, error)`, and `config.IgnoredKey{Line int; Name string}` is new. A slice field on `Config` would have made `Config` non-comparable and broken the `cfg != want` tests. `Name` arrives already escaped and bounded, so `config` stays pure and `cmd` only logs it.
- Unknown keys are no longer stored in the parsed settings map. Nothing read them before this change.
- Key matching is case-sensitive, like `Load`'s own reads. Lower-case proxy spellings are deferred to #45.
- ROADMAP is not updated: it has no row for spec #44 slices. That is left to the run's final integration.
- The escaping helper lives in `config`, not `sanitize`. `config` may import nothing internal, and `sanitize` covers Langfuse payloads.
