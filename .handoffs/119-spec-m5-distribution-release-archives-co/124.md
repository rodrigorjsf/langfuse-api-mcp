## Decisions & deviations
- `ca_cert` has `default: ""`. The MCPB reference resolver (`@anthropic-ai/mcpb` `dist/shared/config.js` `getMcpConfigForManifest`/`replaceVariables`) leaves `${user_config.ca_cert}` literally in the env value when an optional field has no value and no default. The server would then try to load a file named `${user_config.ca_cert}`. With `""`, `config.Load` treats the empty value as unset (`internal/config/config.go`, `Load`: "An empty value counts as unset").
- There is no `compatibility.claude_desktop` range (the Claude Desktop version that supports `platform_overrides` is unknown), no icon, and no `tools`/`tools_generated` (optional, marketplace display only).
- The pack step lives in `scripts/pack-mcpb.sh` (a maintainer procedure with a WHAT/WHY/WHEN/HOW header) because GoReleaser OSS has no MCPB support. The manifest and CLI lockfile are in `packaging/mcpb/`, which `project-structure.md` now names.
- I used a lockfile rather than `npx @anthropic-ai/mcpb@2.1.2`: it pins the transitive tree with integrity hashes, the same approach as the #92 hash-pinned PyYAML. `npm audit` reports `tmp` <=0.2.5 (high, no fix) via `@inquirer/editor`. That package is reached only by the interactive `mcpb init` prompts; `validate`, `pack` and `unpack` never use it. I accepted this and recorded it here.
- The path filter gains `scripts/pack-mcpb.sh`, so a change to the pack script triggers the snapshot run.
- `.gitignore` gains `node_modules/`.
- The invalid-base-URL proof has two halves. The smoke gives the extracted binary the same four variables the manifest maps (the binary behaviour), and the jq check proves the mapping statically. The `${user_config}` substitution itself is proven only by the manual install.

## Learnings
- `~/.local/bin/npm` (mise shim) fails with MODULE_NOT_FOUND. Run `node <mise node>/lib/node_modules/npm/bin/npm-cli.js` instead.
- MCPB reference resolver keeps `${user_config.X}` literally for an unset optional field without a default; give it `default: ""`.
- `echo "x=$(cmd)" >> $GITHUB_OUTPUT` hides a failing `cmd` even under `bash -e`.
