## What was built
- `release.yml` now also triggers on `push: tags: ["v*"]`. Tag runs are never cancelled by the concurrency group.
- On a tag, the build job validates `vX.Y.Z` and exports `RELEASE_VERSION`. It then runs the same GoReleaser `--snapshot` build and checks that the built version equals the tag. `.goreleaser.yaml` `version_template` uses `envOrDefault "RELEASE_VERSION"`, falling back to `0.0.0-SNAPSHOT-<sha>`. All smokes run on the tag's own artifacts.
- The build job now saves both images (`image-amd64.tar`, `image-arm64.tar`) and uploads the image SBOM as its own artifact `image-sbom`.
- The new tag-only jobs are all gated by `if: github.event_name == 'push' && startsWith(github.ref, 'refs/tags/v')`:
  - `sign-blobs` (id-token, attestations) runs after every smoke. It produces `cosign sign-blob --bundle <f>.sigstore.json` for the archives, `checksums.txt` and the `.mcpb`, plus `actions/attest` provenance, and uploads `signed-release`.
  - `publish-image` (packages, id-token, attestations; env `release`) runs after sign-blobs. It loads the smoked tarballs, pushes the per-arch tags, joins them with `buildx imagetools create`, signs with `cosign sign --recursive` by digest, and attests with `push-to-registry`.
  - `publish-npm` (id-token; env `release`) runs after sign-blobs. It publishes the 6 platform tarballs, then the main one, with `--provenance`, and skips any version already on the registry. It authenticates with `secrets.NPM_TOKEN` or OIDC trusted publishing.
  - `github-release` (contents: write) runs after both publish jobs. `gh release create --verify-tag` uploads every archive, SBOM, Sigstore bundle, `checksums.txt` and the `.mcpb`.
- README changes:
  - "Verify what you run" now carries checksum, `cosign verify-blob`, `cosign verify` and `gh attestation verify` commands. It is Planned and says tag-only.
  - The contributors section gains a tag-path paragraph and a "Cutting a release (maintainer, M7)" checklist.
- `security.md` Supply chain and the ROADMAP M5 row are updated.

## Decisions & deviations
- **GoReleaser always runs `--snapshot`, and the tag version comes from `RELEASE_VERSION`.** A non-snapshot run with `--skip=publish` builds no docker image at all (verified: "dockers_v2 builds and pushes images in a single step, so no images will be built while publishing is skipped"). Without the skip, the image would be pushed before any smoke ran. With this design, the publish jobs ship exactly the tarballs and images the smoke tested.
- **The `github-release` job was added**, although the AC does not list it. The README already promises `gh release download` and that the MCPB is "attached to the first release", and the `.sigstore.json` bundles need a home. It is tag-gated, holds only `contents: write` and runs last.
- **Signing runs first.** `publish-image` and `publish-npm` need `sign-blobs`, so nothing is public before the signatures exist. This came from Spec review.
- **Image push.** The per-arch tags `<version>-amd64`/`-arm64` are pushed and then joined into `:<version>`. There is no `latest` tag.
- **Signing and attestation choices.**
  - `cosign sign --recursive` also signs the platform manifests.
  - `create-storage-record: false` avoids `artifact-metadata: write`.
  - SBOMs are covered through the signed `checksums.txt`, not signed individually.
- **npm.** The npm docs describe trusted publishing only for existing packages, so the first publish uses a granular token as a `release` environment secret, and step 7 switches to OIDC. The job keeps `NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}`. Once the secret is gone the value is empty; README step 7 says to remove the line if npm then still asks for a token. This is untestable until M7.
- **GHCR visibility.** A newly pushed package is private (GitHub docs), so README step 7 makes it public.
