## What was built
- The first statement of `main` is `trust.CaptureAmbient()`. It reads `SSL_CERT_FILE`, `SSL_CERT_DIR` (split with `filepath.SplitList`, empty entries dropped), `NODE_EXTRA_CA_CERTS`, `REQUESTS_CA_BUNDLE` and `CURL_CA_BUNDLE`, then unsets only `SSL_CERT_FILE`/`SSL_CERT_DIR`. Go therefore keeps the full OS store.
- The certificates from these ambient sources are added to the trust pool beside the explicit sources.
- A broken ambient source does not fail startup. This covers a missing or empty file, a damaged certificate, a missing directory, and a directory with no certificate. The source is skipped, its report entry gets `warning` and `certificates: 0`, and a `WARN` log line ("CA source not fully loaded") names the variable and path.
- Inside an ambient directory, only the bad files are skipped; the good ones still load.
- `LANGFUSE_MCP_IGNORE_AMBIENT_CA` is parsed with `strconv.ParseBool`. When true, the ambient sources are dropped. Any other non-empty value stops startup with an error naming the variable.
- The report `kind` is `explicit` or `ambient` per source.

## Decisions & deviations
- The capture step lives in `trust` (`internal/trust/capture.go`), not in `config`. The placement table maps "ambient CA variables" to `internal/trust`, and this avoids a duplicate path type. `trust.Build` still never reads the environment; only `CaptureAmbient` does. The spec says trust "does not read the environment itself" about the Build interface, and that still holds.
- The capture result goes straight to `trust.Sources.Ambient` in `cmd`. The ignore flag comes from `config.Load`.
- `config.Load` now returns `(Config, error)`. An invalid ignore value is a startup error, not a silent false: fail-closed for a security flag. This was not in the ticket; it was flagged as small scope creep and kept deliberately.
- Ignored ambient sources are not listed in the report (filed as #25).
- The per-file skip inside ambient directories follows the spec: "skipping unreadable files with a warning for ambient sources". `load(s, strict)` handles both policies.
- The `main` logger is built in `main`, and `run(log, environ, ambient)` gets it. The `io.Writer` parameter was removed.
- The cmd tests' `runExecutable` now blanks all CA variables (`hermeticEnv`) so a developer's own `SSL_CERT_FILE` and similar variables cannot leak into the assertions.
