## What was built
On a deployment whose v4 read family is on, the server registers `get_trace_tree`. An agent passes a `traceId` and gets the whole trace tree in one call. It is a list in depth-first pre-order, and each row carries its `depth` and `parentObservationId`. Roots and siblings are ordered by `startTime` ascending. An observation whose parent is missing becomes an extra root with `orphan: true`. The server follows `meta.cursor` for at most 5 pages of 1000. When pages remain, the result carries `meta.truncated: true` and `meta.cursor`, with a hint to continue through `execute_read`. Input/output and metadata come back only when `include` names them. An empty trace returns an empty result with a hint. The result goes out inside the untrusted-data envelope, sanitized, and is cut at a row boundary at the 100 KiB cap. On deployments without the v4 read family the tool is absent.

## Decisions & deviations
- **API.** The signature is `workflows.GetTraceTree(ctx, *langfuse.Client, sanitize.Redactor, traceID, workflows.Include) (TraceTree, error)`. `TraceTree` holds the sanitized payload, `Empty`, `More`, and `Requests`/`Status`/`Bytes` for the audit line. The path `/api/public/v2/observations` is hardcoded in the workflow, which ADR-0010 allows for typed workflow functions. workflows cannot import catalog.
- **Payload shape.** The payload is `{"data":[rows…],"meta":{"observations":N,"truncated":bool,"cursor"?}}`. `meta.observations` is the number of rows read. Agent-facing hints go in the envelope's `hint`, outside the untrusted data. The envelope's `operationId` is `observations_getMany`, and so is the error's `operationId`.
- **New `sanitize.WrapWith(op, payload, hint, cutHint)`.** Replacing `Wrap`'s hint after the cut pushed the result over 100 KiB, which a test caught. `WrapWith` sizes the envelope with the final hints. `Wrap` behaves as before.
- **"Marked truncated"** for remaining pages means `meta.truncated` + `meta.cursor` + the hint. The envelope-level `truncated` stays reserved for the byte cut, as its doc says.
- **Robustness beyond the ticket, both covered by tests:**
  - Rows caught in a parent cycle become orphan roots, so no row is dropped.
  - Ordering tie-breaks: a missing or unparsable `startTime` sorts last, then rows go by id, then by arrival order.
- **Audit.** `requests` is logged on every tool's audit line: 1 for `execute_read`, 0 for the discovery tools and refused calls. The alternative was a tool-specific key. `audit.operationID` lets a workflow tool name its catalog operation (`observations_getMany`).
- **The continuation hint says "limit of at most 100"**, because `execute_read` caps `limit` at 100.
- **No 24h default time window** (langfuse-api.md "Time windows" says "Planned, M3", #42). A `traceId` query is exempt from that guard, and the ticket asks for none.
- **TDD cadence.** Registration was red → green. The first worked example went red → green with most of the handler, including validation and hints. Later tests passed on first run, so I checked them by mutation: the page cap, orphan marking, cycle handling and root sorting each broke a test.

## Learnings
- `gofmt` is not on bash PATH; use `go fmt ./...`.
- Python heredoc edits turn `​` escapes into literal characters, and gosec G116 then flags the file; edit with `cat <<'EOF'` or escape the backslash.
- Fuzzing through the MCP client: skip `!json.Valid` inputs, because the client refuses to marshal them.
