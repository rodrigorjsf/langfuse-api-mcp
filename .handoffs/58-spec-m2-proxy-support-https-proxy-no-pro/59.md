## What was built
- An operator sets `HTTPS_PROXY` (or `https_proxy`) and optionally `NO_PROXY` in the environment; `execute_read` reaches Langfuse through the proxy (CONNECT tunnel). TLS is still verified against the trust pool.
- Proxy credentials (`user:password@`) go out as Basic `Proxy-Authorization` and never appear in logs, errors, hints, audit lines or tool results.
- `config.Load` validates `HTTPS_PROXY`, `https_proxy`, `HTTP_PROXY`, `http_proxy` from the environment. An invalid value stops startup with `<VAR> (environment): …` and never echoes the value.
- Startup logs one line: `msg=proxy endpoint=scheme://host:port variable=… source=environment noProxySet=bool`, or `endpoint=none`.
- README, `.claude/rules/security.md` and ROADMAP are updated.

## Decisions & deviations
- **Proxy in use.** It is `HTTPS_PROXY`, else `https_proxy`. The `HTTP_PROXY` spellings are validated but never reported as in use: Langfuse hosts are https except loopback, and Go never proxies loopback.
- **Endpoint shape.** The endpoint fills in the scheme's default port: http 80, https 443, socks5/socks5h 1080.
- **Scheme-less values refused.** A value with no scheme (`proxy:8080`) is refused, even though Go would accept it as http. This follows the ticket's rule "parses as a URL with a host and allowed scheme".
- **Extra refusals from review.** Two cases beyond the ticket's list are refused: a percent-encoded host (url.Parse decodes it, so invisible characters or invalid UTF-8 could reach the log) and a port outside 1..65535.
- **Error message example.** Errors cite the example `http://proxy.internal:3128`, so they never contain value fragments such as `proxy.example.com`.
- **Log field names.** The log line uses `endpoint`, `variable`, `source` and `noProxySet`.
- **Test cleanup.** `hermeticEnv` in the cmd tests now clears all six proxy spellings.
- **Shared stdio helpers.** The stdio session helpers (`initialize`, `callTraceGet`, `stop`) moved into `stdio_test.go` and are shared.
