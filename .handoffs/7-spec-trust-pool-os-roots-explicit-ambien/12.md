## What was built
- The server reads `langfuse-mcp/config.env` under `os.UserConfigDir()` (Linux `$XDG_CONFIG_HOME` or `~/.config`, macOS `~/Library/Application Support`, Windows `%AppData%`). No file is fine.
- Format: `KEY=VALUE` per line, trimmed; `#` comments and blank lines ignored; optional dotenv `export ` prefix; BOM and CRLF from Windows editors handled; values taken literally.
- Environment (non-empty) wins over the file; an empty env value counts as unset and does not override.
- A malformed line (no `=`, or empty name) stops startup: `config file <path> line N: expected KEY=VALUE` (line content is never quoted).
- `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` in the file (any case, with or without `export `) stop startup with a message pointing to the environment / client env block; the value is never echoed.
- CA paths from the file are explicit sources (same failure policy). The startup log now carries `"origin":"environment"|"config-file"` per source.

## Decisions & deviations
- `config.Config` fields are now `config.Setting{Value, Origin}`; `Origin` is `environment` | `config-file`. `config.ReadFile()` does the I/O (UserConfigDir error → empty File; ENOENT → empty File with Path; other read error → startup error). `Load` stays pure.
- `trust.Source.Origin` / `trust.SourceReport.Origin` (plain string: trust may not import config) added so the log reports origin (spec #7 story 16). Not an explicit #12 criterion; handoff #10 assigned it here.
- Empty env value does not override the file (consistent with "empty = unset"); recorded as an amendment note in ADR-0011 and in the README rules table.
- Unknown keys are accepted and ignored (host/proxy/flags documented in the file example are not implemented yet) → follow-up #26.
- `ReadFile` reads the real process env via `os.UserConfigDir`, not the `environ` passed to `run`; fine because `main` passes `os.Environ()`.
- `.claude/rules/architecture.md` seam text updated to `config.Load(env, file)`.
