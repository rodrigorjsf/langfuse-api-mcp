# Handoff — #35: Metrics row_limit inside the query JSON is neither defaulted nor capped by execute_read

Status: DONE

## What was built
- `execute_read` now parses the JSON `query` of `metrics_metrics` and `legacy_metricsV1_metrics` before any request is sent.
- If `config.row_limit` is missing, the server sends 100. A value that is not an integer from 1 to 1000 is refused with `invalid_argument` and a row_limit-specific hint. The refused values are 0, 1001, negative numbers, strings, 1.5, null and booleans.
- The query must be a single JSON object. It may be at most 16 KiB and nested at most 10 deep. Only the documented top-level keys are allowed, each with its JSON type. Anything else is refused and Langfuse is not called.
- The server sends the re-encoded query. Duplicate keys collapse to the checked last value, keys are sorted, and numbers are kept exact.
- Error messages never repeat the caller's text. Instructions, bidi characters and markup inside filter values reach Langfuse unchanged, as inert data.

## Decisions & deviations
- The metrics operations are identified by operation ID: an allow-list in `internal/catalog/metrics.go`. They are not identified by parameter shape.
- Only top-level keys are checked. Keys nested inside `config`, `filters` and similar objects pass through for Langfuse to validate. `bins` is not bounded.
- An integral float such as `1000.0` or `1e3` is accepted and sent as a canonical integer. This matches the list `limit` behaviour. The brief says "float → refused", and it is read as non-integral floats. `row_limit: null` is refused, while `config: null` gets the default. Both behaviours are documented in the README.
- The unknown-key error lists the allowed keys but does not name the caller's key. The spec reviewer suggested quoting it. That was declined because quoting would echo caller text, including markup.
- The default of 100 is also injected for legacy v1, whose spec documents no default. This is documented in the README.
- The query-JSON size cap is new: 16 KiB, depth 10. It is recorded on #42 as the shared cap, per the brief: https://github.com/rodrigorjsf/langfuse-api-mcp/issues/42#issuecomment-5846103444
- A new sentinel `catalog.ErrRowLimitOutOfRange` gives the out-of-range error its own hint in `server.executeRead`.
- The fuzz test was written after the implementation. It is a property test, not a red-first slice.
