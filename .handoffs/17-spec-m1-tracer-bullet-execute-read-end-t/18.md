## What was built
- An MCP host can now start `langfuse-mcp` over stdio. The server needs `LANGFUSE_BASE_URL` (or its alias `LANGFUSE_HOST`, which may also come from the config file) and `LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY` from the environment.
- It exposes exactly one tool, `execute_read`. Its annotations are explicit: read-only, non-destructive, idempotent, open-world, with a title. The description says what the tool does, what it returns and what it does not do, and links https://api.reference.langfuse.com.
- `execute_read` takes `{operationId, parameters}` and runs any GET operation of the embedded spec through the generic executor (ADR-0010). Path parameters are percent-encoded. A list value repeats a query parameter. The request goes out with Basic auth through the trust-pool TLS config.
- The result is the Langfuse JSON inside `{label, operationId, data}` (the untrusted-data envelope), returned both as JSON text and as `structuredContent`.
- A missing or invalid host, or a missing key, makes the process exit 1 with one JSON error line on stderr naming the variable. Nothing is written to stdout in that case.

## Decisions & deviations
- **The host is required.** The ticket says a missing host means exit non-zero, but the old README documented a default of `cloud.langfuse.com`. I followed the ticket, updated the README, and filed follow-up #31.
- **Where the host is read.** The host can come from the config file as well as the environment: env `LANGFUSE_BASE_URL`, then env `LANGFUSE_HOST`, then the same two in the file. ADR-0011 and the README already listed it as a file setting.
- **Host validation is minimal.** The host must be an absolute http/https URL with a host part. Requiring https except for loopback hosts is left to #19.
- **Catalog source.** The catalog embeds `spec/langfuse-openapi.json` straight from the `catalog` package via `go:embed`, with no Go package under `spec/`. There are 13 exclusions (ADR-0004), and a test pins the count at 104 operations.
- **Error codes are placeholders.** Minimal tool errors (ADR-0008 shape) exist so the tracer never crashes: `invalid_argument` (bad arguments, non-GET, missing path parameter), `operation_not_found`, and `internal_error` as a catch-all for any client failure. The cause of a catch-all failure is logged to stderr. #19, #20 and #21 replace these with the full mapping.
- **Parameters.** Any parameter that is not a path parameter goes to the query without validation (#19 owns validation). Values may be string, number (via `json.Number`), bool, or a list of those.
- **Client limits.** Transport timeouts and a 5 MiB bounded read (overflow is a plain error) are in place because `go.md` forbids unbounded reads. `response_too_large` is #22.
- **No proxy.** `Proxy` is nil on purpose: proxy settings are M2 and the README still says Planned.
- **No outputSchema.** The tool declares no output schema, because error results carry a different shape from success results.
- **Low-level tool handler.** I used `Server.AddTool`, the low-level handler, so the server controls the `isError` shape. The input schema is hand-written.
- **cmd wiring.** `cmd` wires the server with a `serve` closure, because depguard forbids `cmd` from naming `*mcp.Server`.
- **Dependency.** Added `github.com/modelcontextprotocol/go-sdk v1.8.0`, the official SDK chosen in ADR-0001.
- **Existing tests updated.** The `cmd` tests now start children with a valid connection environment (`connectionEnv`). Config tests go through a `load` helper that adds host and keys.

## Code review
Standards axis:
- **Fixed:** the swallowed client error is now logged to stderr. The keys are no longer printable plain strings in `langfuse.Options`/`Client` (both now redact on String, GoString and LogValue, with a test). The duplicated tool title is now one constant. The receiver `x` is renamed `ex`.
- **Dismissed:** the missing APIError fields and the drained non-2xx body belong to #20. Unknown params and `..` in path params belong to #19. The protocol error that `jsonResult` returns on a marshal failure cannot happen, because it only marshals our own structs and `json.Valid` bodies. Undecoded echoed error text is #22 (sanitizing). ReadAll-then-Valid instead of a streaming decode is bounded and equivalent for a forwarded RawMessage. The `app.serve` closure is required by depguard. The slice literal is trivial. goleak is not in `go.mod` and no existing test uses it. The go-sdk dependency is justified by ADR-0001.

Spec axis:
- **Fixed:** the key missing-check order is now deterministic. S2 now covers an invalid host. The proxy that contradicted the docs is dropped. The secret stays redacted inside the client.
- **Noted as placeholders for siblings:** the timeouts, size cap and minimal error codes.

## Notes for dependent tickets
- `server.New(cat catalog.Catalog, client *langfuse.Client, log *slog.Logger) *mcp.Server`. The translation into tool errors lives in `internal/server/toolerror.go`: `toolError(code, message, hint, operationID)` and `jsonResult(v, isError)`. Add the #20/#21 codes there, and replace the `internal_error` catch-all in `executor.executeRead`.
- `langfuse.Client.Do(ctx, method, escapedPath, query) (Response{Status, Body json.RawMessage}, error)`. Non-2xx answers return `*langfuse.APIError{Status}`, and the body is currently drained and discarded. #20 extends this type and reads the body. Redirect policy (#19), retries (#20), and TLS/network classification (#21) all go in `Do` / `New`.
- `catalog.Operation.Request(params) (catalog.Request{Method, Path, Query}, error)` is the place for #19's validation. `Operation.Params` holds `{Name, In, Required}` decoded from the spec.
- `sanitize.Wrap(operationID, payload) Envelope{Label, OperationID, Data}`. #22 adds Unicode stripping and truncation around it.
- `config.Config.Connection{Host *url.URL, PublicKey, SecretKey config.Secret}`. `Secret.Reveal()` is called only in `cmd` wiring.
- The S2 helpers are `startStdio`/`send` in `cmd/langfuse-mcp/stdio_test.go`. `connectionEnv` in `main_test.go` is the default child environment.
