## Decisions & deviations
- Dependabot cannot bump the `toolchain` directive (dependabot-core#13520 open) → custom weekly workflow; limitations filed as #24. `.claude/rules/go.md` corrected ("Dependabot bumps the toolchain" was false).
- `.github/` is a new top-level directory; treated as platform-mandated (like root tooling files), recorded in `project-structure.md` without a new ADR. ADR-0009 governs Go package layout; `.github/` holds no code.
- depguard: per-module `list-mode: lax` rules = deny `internal/` prefix + allow own package and drawn edges. Added edges server→langfuse (errors.md error types) and server→sanitize (wrapping executor results) to the rule text; `config` is in no allow list, so only `cmd` may import it.
- `os/exec` allowed in `_test.go` only (S2 re-exec); `-race` needs cgo while builds use CGO_ENABLED=0 — both now stated in `go.md`.
- CI installs golangci-lint with `install-mode: goinstall` because a binary built with Go < 1.27 refuses a go 1.27 module.
- govulncheck pinned `golang.org/x/vuln/cmd/govulncheck@v1.8.0`.
- `.gitignore` ignores the root build output (`/langfuse-mcp`, `/langfuse-mcp.exe`, `/dist/`).
- ROADMAP.md not changed: #9 finishes no milestone.

## Learnings
- golangci-lint built with Go < module's go version exits 3 silently; build it with `GOTOOLCHAIN=go1.27.1 go install`.
- depguard `list-mode: lax`: a more specific allow entry overrides a prefix deny.
- `go build ./...` at repo root writes the `langfuse-mcp` binary there (now gitignored).
- Local `golangci-lint` in mise is v2.12.2/go1.26 — unusable for this module.
