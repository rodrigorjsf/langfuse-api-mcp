## What was built
- `get_trace_tree` is registered on every deployment, so a host never refuses a call to it. The tool set is the same for every deployment and every client, fixed at startup.
- Where the v4 read family is off (Langfuse v3, or v4 in a legacy mode), a call whose arguments pass the checks answers `operation_unavailable`: a fixed message naming the deployment's version, and a fixed hint naming `trace_get` (when the resolved catalog offers it), `search_operations`, then the deployment's version and families on and off. No Langfuse request is sent.
- Argument checks (`traceId`, `include`, unknown arguments) run first and are unchanged: an invalid call is `invalid_argument` on every deployment.
- The audit line of the refused call: `tool` get_trace_tree, `operationId` observations_getMany, `method` GET, `status` 0, `bytes` 0, `requests` 0, `code` operation_unavailable.
- On a deployment with the v4 read family the tool behaves as before (only the tool description gained a sentence about the v3 answer).
- Docs: README tool table, `docs/reference/tools.md` (tool row and error table row), `CONTEXT.md` (Unavailable operation), `ROADMAP.md`, `docs/reference/security-model.md`, `docs/research/security.md` (mapping row #74), `.claude/rules/security.md`, `.claude/rules/errors.md`, ADR-0002 amendment marked shipped.

## Decisions & deviations
- The error's `operationId` is `observations_getMany`, the operation the trace tree reads and the one the other `get_trace_tree` errors and the audit line already name. Kept for consistency with #174's convention (the unavailable operation's own ID); `trace_get` is in the hint.
- The hint names `trace_get` only when the resolved catalog offers it (a read operation); otherwise it says the deployment offers no operation that reads one trace. It does not reuse `Catalog.Unavailable("observations_getMany")` because that reverse mapping lists six legacy operations on 3.80.0, not the one that reads a trace.
- The availability check is `profile.On(catalog.V4ReadFamily)`, the same condition that used to decide registration. `discovery.offersTraceTree` was removed; `traceReadsHint` reads the profile directly (follows #174's note for dependent tickets).
- ADR-0002's old registration bullet now points to the amendment; the amendment's "Planned for M8" now says shipped in M8 (#174, #175), following the #173 precedent in ADR-0012.
- ROADMAP M8 status cell appended "`get_trace_tree` on every deployment shipped (#175)"; the M3 row notes the later change. M8 as a whole stays Planned.
- The user skill is untouched, as the spec requires.
