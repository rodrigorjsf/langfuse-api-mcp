## What was built
- On a deployment where `get_trace_tree` reads the legacy observations list (legacy family on, v4 read family off), each row now comes back without the top-level keys Langfuse sent as JSON `null`. An absent key means `null`.
- `id`, `parentObservationId` and `startTime` are kept whatever they hold, so a root still shows `parentObservationId: null`. `0`, `false`, `""`, `{}`, `[]` and the text `"null"` stay; nothing inside a value changes (with `include`, a nested `null` stays, a top-level `null` `input`/`output`/`metadata` goes).
- The rule runs on the cleaned and redacted page, as the removal of `input`/`output`/`metadata` does, before the ordering is written and before the result size cap. Observations v2 rows, `execute_read` of `legacy_observationsV1_getMany` and the filter scan are unchanged.
- The tool keeps one static description; it gained: "On the legacy list a field that Langfuse returned as null is left out, so an absent field means null; id, parentObservationId and startTime are never left out for being null. Observations v2 rows keep their null fields." "not translated" stays.
- Size, measured: **130 observations do NOT fit the default 64 KiB cap.** See Decisions & deviations.

## Decisions & deviations
- **Measured outcome: 130 observations do not fit.** The ticket allowed this ("the ticket is still done"): no second rule was added. Numbers (default cap 64 KiB = 65,536 bytes):
  - Recorded 3.80.0 row (span, no model/usage/cost, has `endTime`): 865 bytes raw, 18 of 39 keys `null`; **527 bytes in the result** (key order sorted, `depth` added, `input`/`output`/`metadata` removed).
  - **124 observations fit whole** (65,531 bytes); of 125 the tree returns 123 rows truncated; of 130, 123 rows (hint: "only the first 123 of 130 rows fit"). Before the rule: 78 of 130 on the same fixture (measured by switching the rule off).
  - Live 3.80.0 130-observation trace (spans with start time only, so `endTime`/`latency` are `null` too): **125 of 130 rows**, truncated, hint "only the first 125 of 130 rows fit the result size cap"; before: 76 of 130 (#187).
  - So "about halves a row" held only partly: 870 to 527 bytes (about 40% smaller), which moves the limit from about 75 to 124 observations, not to 130.
  - The row counts depend on the byte length of the truncation hint; if its wording changes, both the seam table and `liveRowsAtTheDefaultCap` must be measured again (comments say so).
- Rule lives in `workflows.dropNullKeys` (called per row right after `Include.dropUnrequested`); matches the compact cleaned raw value `null`; deleting while ranging over the map. `keptWhenNull` and the new constants `keyID`, `keyParentObservationID`, `keyStartTime` in `trace.go` are shared with the ordering code (review: the three literals were duplicated).
- Duplicate keys: `{"id":"r","id":null}` is one key once decoded (last wins, existing #187 behaviour); the rule never removes a kept key, so the row is still returned. Not changed.
- Description wording: "never left out for being null" rather than "always present", because a row Langfuse sent without the key has none (review, Spec axis).
- Test-helper refactor outside the ticket's files: `connectClientTo(t, srv, opts)` added to `server_test.go` and used by the new test and by the two existing copies (`tracetree_unavailable_test.go`, `scannedfilters_test.go`), which were byte-for-byte or near copies; behaviour of those tests unchanged.
- `CONTEXT.md` not changed: **Trace tree** is still true as written and the rule is behaviour, not vocabulary (the file is a glossary only).
- The live test run needed the pinned stack; the preflight guard passed (MemAvailable about 6.9 GiB, no other containers), so the live criteria were run, not deferred.

## Learnings
- Editing tools can turn a `​`-style escape typed in a Go raw string into the real character (gosec G116 "Trojan Source" and staticcheck ST1018 then fail lint). After writing tests with JSON escapes, run `LC_ALL=C grep -nP '[\x{200b}-\x{200f}\x{202a}-\x{202e}\x{2066}-\x{2069}]' <file>`, or write the file through Python with `chr(92)`.
- `gofmt` and `go` are not on the bash PATH; `export PATH=$HOME/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-amd64/bin:$PATH GOMEMLIMIT=2GiB` first (same as the #187 handoff).
- A fixture row for a live-recorded API response: record it from the pinned stack with `curl -u pk:sk .../api/public/observations?traceId=…` after a `curl .../api/public/ingestion` of a trace and a span; the row shows up about 5 s later.
