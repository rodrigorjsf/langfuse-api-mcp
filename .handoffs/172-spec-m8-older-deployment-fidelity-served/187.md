## What was built
- On a deployment where the legacy family is on and the v4 read family is off (Langfuse v3, or v4 in a legacy mode), `get_trace_tree` returns the trace tree instead of `operation_unavailable`. It reads `legacy_observationsV1_getMany` filtered by `traceId`, 100 rows a page from page 1, for at most 10 pages, and orders the rows like the v4 path (depth-first pre-order, `depth`, `parentObservationId`, siblings and roots by `startTime`, `orphan: true` for an absent parent, `meta.observations` and `meta.truncated`).
- The legacy list always sends `input`, `output` and `metadata`; the server removes them from every row (by key name, top level, after the page is cleaned) unless `include` asks for them.
- A tree that stops at 10 pages says `truncated` with a static hint naming `legacy_observationsV1_getMany`, `traceId` and the next page number. A trace with no observations is an empty result with a hint after one request. A failed page (a page over the read cap included) ends the call with its tool error, no partial tree; a page over the read cap gets a hint that names the paging the legacy list has.
- Where the v4 read family is on (whatever the legacy family is), the tool reads Observations v2 as before. Where neither family is on, it answers `operation_unavailable` with no request (#175, moved tests).
- The tool keeps one static description for every deployment (names both sources and both latency units). The trace reads hint of `search_operations` on a legacy deployment names `get_trace_tree`.
- Docs: ADR-0002 amendment (decision, bounds, rejected source `trace_get`, replaces the "deferred" sentence), ADR-0012 §6 pointer, README, `docs/reference/tools.md` (tool row, error table, new section), `security-model.md`, `docs/research/security.md`, `docs/research/langfuse.md` §1.12 (live facts), `.claude/rules/{security,errors,project-structure}.md`, `CONTEXT.md`, `ROADMAP.md`, `docs/development/integration-tests.md`.

## Decisions & deviations
- Started from the interrupted attempt's patch (`187-partial.patch`), applied clean, then verified instead of trusted: full suite, lint, live run on 3.80.0, and mutation checks (see Verification).
- Source choice is made from the profile: v4 read family on → Observations v2; else legacy on → legacy list; else `operation_unavailable`. The `trace_get` branch of the unavailable hint can no longer fire in production (the catalog never offers `trace_get` when the legacy family is off) but stays, as the ticket asks for the #175 tests to move, not be deleted.
- Each legacy page is run through `sanitize.Payload` before its rows are read, so `input`/`output`/`metadata` are removed by the name the agent would read (a key written with a hidden character or escape cannot keep them).
- `meta.totalPages` decides the end of the list (shared `endOfList` with the filter scan); without it only an empty page does. A `totalPages` that is not a number is `internal_error`; no value raises the 10-page ceiling.
- Hint for a page over the response read cap is specific to the legacy tree (spec story 58): `execute_read` with `legacy_observationsV1_getMany` and a `limit` below 100. The v4 tree keeps the generic hint (unchanged behaviour).
- Deviation, filed as #200: the ticket says the default result is "as small as on v4" and returns every observation with only large values clipped. On the real 3.80.0 a legacy row is about 870 bytes even without input/output/metadata (39 keys, mostly null), so a trace over about 75 observations loses rows at the default 64 KiB cap. Closing it means dropping null keys or an allow-list, which contradicts "the rows are not translated" in the ticket and ADR; it needs a maintainer decision. Docs state the effect (tools.md "Row size", ADR-0002 consequences, research §1.12). The wording "as small as on v4" was changed to "carries none of the three".

## Learnings
- The `internal/server` test package grows past 6 GB RSS under the default GC on this 8 GB WSL machine (already at the base commit, with `-race` or not); a full run can take the machine down. Run the suite with `GOMEMLIMIT=2GiB` (suite then takes about 2.5 min with `-race`).
- `go` is not on the bash PATH here; use `~/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-amd64/bin`.
- `pkill -f <script>` from a bash tool call kills the tool call itself when the script name is in its command line.
- Direct calls to the pinned 3.80.0 stack: the keys are in `.env.integration.selfhosted` (gitignored) in the directory `langfuse-selfhosted.sh up` ran in.
