## What was built
- `server.New` now takes a `langfuse.DeploymentProfile` (version + families on). Every `operation_unavailable` hint ends with `deployment: Langfuse <version>; families on: …; families off: …`.
- The version is untrusted: it is shown only when it is a plain `major.minor.patch`. Anything else, including instructions, bidi/control characters or markup, reads `Langfuse version unknown`.
- The events_only flavour names the legacy family and the v4-write-mode flavour names the v4 read family. The HTML-404 flavour points at the families-off list.
- Startup passes `langfuse.UnknownProfile()` (version unknown, every family on) until #72 wires detection.
- The Langfuse body is still never echoed.
- README error table row updated.

## Decisions & deviations
- **Ticket order.** #34 was scheduled before its natural home #72, which is blocked by #71. I built only the value side: the profile type, the `server.New` parameter and the hint. Detection is not built, and startup passes `UnknownProfile()`.
- **Profile placement.** `DeploymentProfile`, `Family`, `AllFamilies()`, `UnknownProfile()`, `KnownVersion()` and `On()` live in `internal/langfuse/profile.go`, because detection belongs there (project-structure.md). Both reviewers flagged that `internal/catalog` cannot import this type. That is filed in #78 for #71/#72 to settle.
- **HTML 404 hint.** It names the families off, not the called operation's own family, because the catalog has no per-operation family yet. Filed as #78.
- **Version pattern.** `^[0-9]{1,5}\.[0-9]{1,5}\.[0-9]{1,5}$`. A leading `v` or a prerelease tag reads "unknown"; #72 may normalise before storing.
- **TDD.** The unknown/injected-version tests went green on first run, because `profileSummary` handled "unknown" in the first green step. That was slight anticipation, not a red-first cycle.
- **ROADMAP.md not edited.** M3 stays "planned" because this is a partial slice, and editing that shared row would conflict with the parallel tickets #36 and #65.
