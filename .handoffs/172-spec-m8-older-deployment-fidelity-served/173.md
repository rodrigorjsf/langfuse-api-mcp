## What was built
- The catalog generator records `x-introduced` / `x-removed` for every path and query parameter; the embedded union catalog is regenerated with them (up to v4.50.0).
- `catalog.Resolve` resolves each operation's served parameters for the detected version. `describe_operation` lists only those (on 3.80.0: no `traceId` on `scores_get-many`, no `level` on `legacy_observationsV1_getMany`, no `fields` on `trace_get`).
- `execute_read` / `execute_write` refuse a not-served parameter with `invalid_argument` before any request. The message names the parameter, the operation, the deployment version and the serving release (`from 3.133.0`, or `up to before X`); the hint is static ("call again without it and filter the rows yourself over every page").
- An unknown name keeps the old unknown-parameter refusal. With no detected version the newest release's parameters are served and startup logs `Langfuse version not detected: serving the newest release's parameters`.

## Decisions & deviations
- Base main was already red on 4 tests after the v4.50.0 catalog regeneration (counts 119->120 and 68->69; `unstable_skills_getFileContent` renamed `...Contents` in 4.48.0 for the "newest known" row). Fixed the fixtures (absorbed).
- Generator drops a path/query parameter with an object schema: releases 3.57.1-3.78.x list `datasetRunItems_list`'s response schema as a required query parameter `response`; kept, it would be required on those deployments.
- Catalog regenerated with a one-off filter to releases <= v4.50.0 (the committed newest), to avoid unrelated drift from v4.51-4.56 (which changed the op set and broke fixtures). Identical result reproduced a second time. The weekly job will move it forward.
- Parameter gaps (a release between two that list a parameter) are ignored like operation gaps and noted on stderr; none exist for query parameters in the real specs (only the known v3.28.2 operation gap and its two path parameters).
- Type/enum changes between releases are not tracked (per ADR).
- The `Operation` carries unexported `unserved` and `deployment`; `Param` gained exported `Introduced`/`Removed`.
- No write operation has a ranged parameter; security.md says so instead of claiming a write-seam test.
