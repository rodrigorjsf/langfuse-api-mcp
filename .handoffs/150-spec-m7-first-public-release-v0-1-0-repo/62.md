## What was built
On Windows, the environment map that feeds `config.Load` is keyed by `config.WindowsEnvName`: every name is upper-cased, except the lower-case proxy spellings (`https_proxy`, `http_proxy`, `no_proxy`), which keep theirs so the startup log names them as stored. So `Https_Proxy` or `Langfuse_Mcp_Rate_Limit` is found, validated and redacted exactly like `HTTPS_PROXY` / `LANGFUSE_MCP_RATE_LIMIT`, and errors/logs name the upper-case variable. Linux and macOS are unchanged (names as stored, upper-over-lower). README and ROADMAP updated.

## Decisions & deviations
- Lower-case proxy spellings keep their spelling (spec: "stay findable"); every other name, including all-lower-case `langfuse_*`, is upper-cased so the LANGFUSE_* AC holds for any casing.
- A mixed-case proxy variable is logged/named as `HTTPS_PROXY` (canonical), not as stored. Acceptable: Windows treats them as one variable.
- Rule lives in `internal/config` (`WindowsEnvName`, next to the spelling pairs); `cmd` only chooses to apply it when `runtime.GOOS == "windows"`.
- Windows tests were run locally by cross-compiling (`GOOS=windows go test -c`) and running the `.exe` on the Windows host from WSL. The only Windows failure there, `TestExecutableReportsTheVersionInjectedAtBuildTime`, is environmental (no `go` on the Windows PATH) and pre-existing; CI's Windows runner has Go.
- The config file is not affected (its keys keep their documented exact matching).
