## What was built
- The operator can set `LANGFUSE_MCP_RATE_LIMIT` (requests per minute, from 1 to 60000, default 30) and `LANGFUSE_MCP_MAX_CONCURRENCY` (requests in flight, from 1 to 64, default 4). Either can come from the environment or the config file, and the environment wins. A value that is zero, negative, non-numeric or out of range stops startup, and the error names the variable. It is never clamped.
- One shared `rate.Limiter` and a slot semaphore inside `langfuse.Client` cover every attempt, retries included. The slot is taken first and the rate token second, so requests waiting in the queue cannot all leave in one burst.
- The limiter's burst equals the concurrency cap.
- A wait that cannot finish before the request deadline is not sent. It returns `langfuse.ErrThrottled`, which wraps `ErrTimeout`. The server reports it as tool error `timeout` with `retryable: true` and a fixed message and hint. A cancellation returns `canceled`.
- If the limits hold a retry past the deadline, the agent gets the Langfuse failure that caused the retry, not the throttle error.

## Decisions & deviations
- A zero in `config.Config` means "unset", and `langfuse.New` applies `DefaultRateLimit` or `DefaultMaxConcurrency`, as `RequestTimeout` does. This keeps `Config` comparable to its zero value in the existing tests, and it defines the defaults in one place. The config ranges still reject an explicit 0.
- The default rate is 30/min, the Hobby General limit. The brief asks for defaults that are both "generous" and "still protecting Hobby", which conflict. I chose protection and filed #47 for the maintainer to confirm.
- The burst equals the concurrency cap, so a full parallel fan-out leaves at once.
- A throttled call reuses the existing `timeout` code (as the issue body asks) with `retryable: true` (as the security comment asks). No new public error code was added.
- New test seam: `langfuse.Options.Now` (the clock), alongside the existing `Wait`.
- `golang.org/x/time` moves from an indirect to a direct dependency. It was already allowed by go.md.
- `.claude/rules/errors.md` gained one mapping row, and `.claude/rules/security.md` now names the variables. CONTEXT.md gained the term "Request limits". ROADMAP was not touched: it has no per-slice row, and line 39 cites #37 only as an example.

- (Spec) The rate token was taken before the slot, so queued requests could burst past the rate, and a slot timeout lost its token. The order is now slot first, then token, covered by a new test.
- (Spec) A throttled retry hid the 5xx/429 that caused it. The cause is now returned, covered by a new test.
- (Standards) No fuzz target existed for the new parser. Added `FuzzLoadLimits`, fuzzed for 15 s with no failures.
