## What was built
- The offline user skill check `scripts/check-skill.py` (spec #132 seam S3) fails a skill when:
  - its `SKILL.md` frontmatter lacks `name` or `description`, or `name` is not the directory's name;
  - the entry file cites a reference that does not exist;
  - a lowercase snake_case word is not a known tool name, a known error code or a catalog operation ID;
  - the text holds a forbidden phrase.
- The known tool and error-code lists sit in the check and name the `internal/server` files they are kept in step with. The tests read those files and fail on any drift.
- CI (job `generator`) runs `test_check_skill.py` and `check-skill.py` right after the eval's offline tests. The `ci.yml` trigger moved from `paths-ignore` to `paths` with a re-include of `skills/**`, so an edit to skill Markdown alone now starts CI.
- These parts came from #98 (already in the base) and were checked, not rebuilt: the entry file, the traces reference, the eval's `--system-append` option and the intent-03 A/B record.

## Decisions & deviations
- **Delivered only the missing parts.** #98 already delivered the entry file, the traces reference, `--system-append` and the A/B. This ticket delivered only S3 and its CI wiring.
- **Unknown-word rule.** The check scans lowercase snake_case words, not only words in backticks, so a tool name in the description is checked too. Some v4 operation IDs are lowercase snake (`prompts_get`), so every operation ID of the embedded catalog is accepted. Mixed-case IDs such as `observations_getMany` are not checked (documented).
- **Drift guard.** The tests read `internal/server`, so drift fails CI. The guard found 4 codes in `failure.go` that my first list missed: `tls_untrusted_certificate`, `network_error`, `timeout`, `canceled`.
- **Negation.** A forbidden phrase fails even when negated ("never skip the confirmation"). This is intentional: it is the stricter reading of the spec. It is documented in the script header and the README, and proven by `test_a_negated_forbidden_phrase_still_fails`.
- **CI trigger.** Moved from `paths-ignore` to `paths`: without it, S3 would never run on a skill-only edit. The ordering is last match wins. Assumption: GitHub's `**` matches dot-paths (`.golangci.yml`, `.github/**`). This cannot be verified offline; confirm it on the next PR that touches only a dotfile.
