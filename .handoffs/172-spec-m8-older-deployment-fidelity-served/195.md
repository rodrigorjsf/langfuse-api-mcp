## What was built
`execute_read` (and `execute_write`, through the same `Operation.Request`) now reads a JSON `filter` as it reads a metrics `query`. A closed list in the catalog names the seven operations whose `filter` is a JSON text (`trace_list`, `legacy_observationsV1_getMany`, `observations_getMany`, `scores_get-many`, `experiments_list`, `experiments_listItems`, `prompts_list`). Such a filter must be a string holding one JSON list, at most 16384 bytes and 10 levels deep, with no control or invisible character as raw text or in any decoded string or key, so a JSON escape of one is refused like the character itself. The server sends the list it checked, written again as compact JSON: conditions and list items in order, numbers as written, object keys sorted, a duplicated key once with its last value, no escape of a hidden character or of half a surrogate pair. Anything else is `invalid_argument` naming `filter` and the rule or bound, never the value, with one static hint. The `filter` of `scim_listUsers` (a SCIM expression) is an ordinary query value and loses the tab/LF/CR exemption it had by its name. `describe_operation` is unchanged.

## Decisions & deviations
- `prompts_list` `filter` is a JSON filter. Source: the release specs `v4.42.0` and `v4.46.0` (`web/public/generated/api/openapi.yml`) describe it as "JSON string containing an array of filter conditions, combined with AND" and say an empty array applies no filters; the API reference (`langfuse-docs` MCP, 2026-10-11) lists no `filter` for the operation. Recorded in `docs/research/langfuse.md` section 1.15 and as mismatch row 14 in section 6. The test that sent the word `billing` now sends a JSON list.
- Check order: raw hidden character, size, depth, decode, list, trailing data, decoded hidden character, re-encode. A first draft checked the size first; the Spec reviewer found that a raw hidden character in a filter over 16 KiB then got the size message instead of "today's refusal and message". Reordered; a table row covers it.
- Every refusal of a JSON filter (the raw hidden character included, whose message is unchanged) carries the filter hint, not the generic parameters hint. The wrong-argument-type case (`want a string, got a list`) gets it too.
- The hint is built in `internal/server` (`jsonFilterHint`) from `catalog.JSONFilterEncoding()`, as the metrics hint is built from `catalog.MetricsQueryEncoding`; the bounds in it are the catalog's constants.
- The metrics query's bounds and helpers were generalized, not copied: `maxMetricsQueryBytes`/`Depth` became `maxJSONTextBytes`/`Depth`, `checkDepth` became `tooDeep`, and `decodeJSON` and `encodeJSON` are shared. Metrics messages are byte-identical (existing metrics tests pass unchanged).
- Re-encoding with Go's encoder writes U+2028 and U+2029 as six-byte escapes, so an accepted filter can be sent longer than it was received (a 15004-byte filter of those characters became 30004 bytes). The ticket bounds the input, not the output; neither character is in the hidden set of #179. Accepted as is; the fuzz sends the text again only while it fits the bound.
- Lone surrogate escapes become U+FFFD in the text sent (ticket decision 3: the text sent holds no escape that decodes to half a pair); Langfuse's own reader would have kept the lone half.
- The fuzz oracle is independent of the code: it decodes the text sent and walks every string and key, and scans the escapes of the text itself with a small reader of its own.

## Learnings
- The `server` package cannot run under `-race` as one process on an 8 GB machine today (base commit included): use `-test.list` and run the race binary in chunks under an RSS guard, or wait for #201.
- The Write tool turns `�` in typed source into the real character; build such strings from code points (`string(rune(0xfffd))`) and run `grep -nP '[^\x00-\x7F]'` on new Go files (same trap as #179, now also in a string with a capital hexadecimal letter).
- `gosec` G115 flags `rune(uint64)`: read a `\uXXXX` code unit with `fmt.Sscanf("%04x", &r)` into a `rune`.
- `go` is not on the bash PATH here; `export PATH=$HOME/.local/bin:$PATH` (go 1.27.1 through mise).
- Go's JSON encoder always writes U+2028 and U+2029 as escapes, `SetEscapeHTML(false)` or not.
