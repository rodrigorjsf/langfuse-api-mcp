# Handoff — #45: Config-file proxy keys (both spellings) reach the Langfuse client

Status: DONE
Spec: #58   Ticket: #45
Branch: spec/58-spec-m2-proxy-support-https-proxy-no-pro--45   Base: fd236bea9fa4aa85fe27d08d18d52a361ba73f7d   Head: 5acc31f (plus this handoff commit)

## What was built
- The config file can set `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY` in either spelling. `https_proxy`, `http_proxy` and `no_proxy` are known keys and draw no warning. This is the only case exception: a lower-case `langfuse_ca_cert` is still warned about.
- Precedence:
  - A variable the environment sets in either spelling is read from the environment only.
  - Within each source, the upper-case spelling wins.
- A config-file proxy value is validated like an environment one. An error names `config file <path> line <n>: <VAR>` and never includes the value.
- The startup `proxy` line shows `"source":"config-file"` when the proxy in use came from the file.
- The Langfuse client's proxy function is built from these resolved settings (`langfuse.ProxyFromSettings`, using `golang.org/x/net/http/httpproxy`). The process environment is never written.

## Decisions & deviations
- **Mechanism: #61 option 1, decided autonomously.**
  - The spec's mechanism can never work in this binary: export the file keys with `os.Setenv`, then rely on `http.ProxyFromEnvironment`, with no `x/net` dependency. go-sdk v1.8.0 `oauthex` freezes `ProxyFromEnvironment` at package init. Attempt 1 proved this, and the `os.Setenv` build failed the process tests again in this run.
  - What replaces it:
    - `config.Load` returns `Config.ProxySettings{HTTPS, HTTP Secret; NoProxy string}`.
    - `cmd` passes them to `langfuse.ProxyFromSettings`, which wraps `httpproxy.Config.ProxyFunc`.
  - Recorded in an ADR-0006 rewrite (the proxy sentences now state only the mechanism in use and why), with comments on #61 and spec #58.
- **New direct dependency `golang.org/x/net v0.59.0`.**
  - It raised the indirect dependencies `x/sys` (0.41 to 0.48) and `x/sync` (0.20 to 0.23), and added `x/text`.
  - `govulncheck` (v1.8.0) reports `No vulnerabilities found.`
  - `.claude/rules/go.md` lists `x/net/http/httpproxy` under "Allowed extras".
- **CGI flag omitted.** The `httpproxy` CGI mode (`REQUEST_METHOD`) is not replicated. It only affects `http://` requests, which reach only loopback here, and loopback is never proxied.
- **Values the file trims are skipped in the matrix.** Four cases of the refusal matrix are not run for file values, because the file parser trims them (`strings.TrimSpace`) or ends the line: newline, tab, leading whitespace, and non-breaking space.
- **Proxy failure classification (#32) is untouched.**

## Code review
Standards axis:
- **Fixed:**
  - The proxy function lived in `cmd` (project-structure.md puts proxy in `langfuse`; go.md says "cmd only wires"). It is now `langfuse.ProxyFromSettings`.
  - go.md's allowed-extras list is updated.
  - ADR-0006 no longer contradicts itself.
  - `loadProxy` used positional array indexes. It now uses named pairs and a `resolve` helper.
- **Dismissed:**
  - Duplication with `Load`'s `setting` closure: the proxy resolution works per spelling pair, and the closure is single-name.
  - Data Clump `fromFile`/`lines`/`path`: a parsed-file type would refactor `parseFile` for every caller, which is out of scope.
  - `Proxy` derived from `ProxySettings`: `Proxy` carries the variable spelling and origin, which the settings do not.
  - A `CONTEXT.md` term for proxy: proxy is a standard networking term, as #59 already decided.

Spec axis:
- **Fixed:**
  - The file-side refusal matrix was missing; it now runs.
  - ADR text was stale.
  - The indirect-dependency bumps were undocumented; ADR-0006 now mentions them.
  - Spec #58 still described the old mechanism. The body was not edited; a comment on #58 points to #61 and ADR-0006.
- **Follow-up:** Windows mixed-case variable names (`Https_Proxy`) are now ignored, whereas `ProxyFromEnvironment` found them. Filed as #62.
- **Dismissed:** the ticket's "config file" wording against the logged `config-file`. The log uses the existing `OriginConfigFile` value, and the README documents it.

## Learnings
- go-sdk `oauthex` freezes `http.ProxyFromEnvironment` at init; build proxy funcs from resolved config.
- `govulncheck@v1.1.4` panics under go1.27; use `govulncheck@v1.8.0`.
- The `gofmt` binary is not on PATH in bash; use `$(go env GOROOT)/bin/gofmt`.

## Notes for dependent tickets
- The Langfuse client's proxy option is `langfuse.ProxyFromSettings(httpsProxy, httpProxy, noProxy string)`, fed from `config.Config.ProxySettings`. #32's CONNECT classification plugs into the transport; the proxy function is unaffected.
- `http.ProxyFromEnvironment` is no longer used anywhere in production code. Do not reintroduce it: it is frozen at init.
