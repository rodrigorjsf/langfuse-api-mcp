## What was built
A Langfuse key (`pk-lf-…`, `sk-lf-…`) is now redacted when it directly follows a JSON escape written as text: one or more backslashes then `b`, `f`, `n`, `r` or `t`, or `u` and four hex digits. That is how a line feed reads inside a string that holds JSON text (the Observations v2 `input` and `output`, stringified once or more), where the escape letter used to hide the word boundary. The escape stays character for character, so the string is still valid JSON text and decodes to the same value with the key replaced. Everything else in the redactor is unchanged. The single change is the key pattern in `internal/sanitize/redact.go` (`keyPattern`, new constant `wordEndedEscape`), so every place a key is redacted (payload strings and keys, Langfuse error text, echoed names, the confirmation text, the audit line, the last pass over a result) gets it.

## Decisions & deviations
- Single regexp with a capture group: `(?:\b|(` + wordEndedEscape + `))[ps]k-lf-[A-Za-z0-9_-]+`, replacement `${1}[REDACTED]`. The two alternatives cannot match the same key (the escape ends in a word char, so `\b` cannot fire there). A two-pass design (old pattern, then an escape pattern only if `k-lf-` remains) would be faster on text full of keys (3.4 ms vs 1.77 ms per 64 KiB) but adds a second pattern for a rare text; not done. Reversible if a measurement ever asks for it.
- Escapes of a quote, backslash and slash need nothing: they already end in a non-word char.
- The fixed point for hidden characters: `Redact` returns the original text when nothing was redacted, so the "stripped character glues the key to a word" limit is pinned through `Payload`, which always cleans, not through `Redact`.
- Pinned documented limits (tests): glued letter/digit/underscore, stripped-character glue, split key up to the escape, M1 (escaped control character inside JSON text stays, `TestPayloadKeepsAControlCharacter…`), key after a line break the confirmation drops (`TestAKeyAfterALineBreakThatTheConfirmationDrops…`, a leak shown to the user in the confirmation text, as designed by the ticket).
- Docs state each limit in its own sentence (second comment on the ticket) and cite #210 and #211 in the security rule; the user references carry no issue numbers (their convention).
- Compact, sorted-key fixtures, as the ticket's second comment asked; literals for stringified once, twice, three times were derived with an independent encoder (Python), not with the Go code under test.

## Learnings
- The tool harness turned a typed backslash-u + 4 hex digits into the real character in some command and file contents (a zero-width space ended up in test sources). Build such text from pieces (`chr(92)` in Python, `` `\` + `u200b` `` in Go) and grep for non-ASCII after writing.
- `git stash push <file>` also takes that file out of the index; to run tests against the base version of a file, `git show <sha>:<path> > <path>` and copy the fix back.
- `gofmt` is not on the bash PATH here; use `$(go env GOROOT)/bin/gofmt`.
