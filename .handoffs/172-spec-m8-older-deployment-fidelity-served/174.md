## What was built
- `describe_operation`, `execute_read` and `execute_write` answer `operation_unavailable` for an ID that is in the union catalog and absent from the deployment's resolved catalog. Message and hint are static: the catalog's own operation ID, the operations to use instead, `search_operations`, then the deployment (version, families on and off).
- Replacements come from the catalog: the operation a legacy summary says to prefer (forward) and the offered operations whose summary prefers this one (reverse), same HTTP method, in ID order.
- A legacy line of the operation index names a preferred operation only when the resolved catalog offers it; otherwise the line reads "... (legacy)". On 3.80.0 no line holds "prefer".
- The trace reads hint of `search_operations` now exists on a deployment without the v4 read family, naming `trace_get`, `trace_list`, `legacy_observationsV1_getMany`, `legacy_metricsV1_metrics` as offered.
- Docs: `docs/reference/tools.md`, `docs/reference/security-model.md`, `docs/research/security.md` mapping row, `.claude/rules/errors.md`, `.claude/rules/security.md`. The user skill is untouched.

## Decisions & deviations
- Each tool answers `operation_unavailable` only about operations it runs: `execute_read` about GET, `execute_write` about non-GET, `describe_operation` about both (a write only in write mode). The other kind stays `operation_not_found`. This narrows the literal "all three tools for any ID" so a tool never names operations it cannot run; found by the Spec/Standards review.
- Hint wording "operations to use on this deployment instead" (not "do the same job"): the reverse mapping lists every legacy operation that prefers the ID (six for `observations_getMany` on 3.80.0), not one equivalent.
- The forward mapping (legacy ID on v4 names its preferred operation) is also answered, consistent with parent story 24.
- The preferred operation is recovered from the generator's `x-summary` text ("legacy: prefer X when it is available") at catalog load, validated against operation IDs actually in the resolved catalog. Judgement: a structured generator field would be sturdier but needs a network regeneration; tests fail if the wording changes.
- Absorbed: the base was red because the union catalog was regenerated to 4.50.0 without updating test counts (120 operations, 69 GET, `unstable_skills_getFileContents` replaces `getFileContent`) — fixed in `catalog_test.go`, `index_test.go`, `resolve_test.go`, `discovery_test.go`. `datasetRunItems_create` line now reads "(legacy)" because its preferred operation is excluded (ADR-0004).
- `cmd/langfuse-mcp/stdio_test.go`: `trace_get` on a 4.46.0 `events_only` profile now expects `operation_unavailable` (was `operation_not_found`).
- ROADMAP.md not edited: M8 stays Planned as a whole milestone.
