## What was built
- **Outcome A.** One race-detector process of `internal/server` now peaks at **1628 to 1761 MiB** (five `/usr/bin/time -v` runs; 1579 MiB by `scripts/race-memory.sh`) and ends in 23 to 26 s. On the base commit it passed 5000 MiB after 41 s and a guard killed it. `go test -race ./...` is unchanged and passes with the default `-timeout` (server package 33 to 38 s).
- **Cause, verified:** the tests kept what they built. Go 1.27.1 `testing` keeps every finished parallel test (the root test's `sub` list, `testing.go:1937`) together with its `t.Cleanup` closures (`runCleanup` shortens `c.cleanups` without clearing it, `testing.go:1811-1814`). The helpers' session cleanups held the server, so each finished test kept its server and its catalog until the run ended. The server itself keeps nothing (no product fault; `internal/` non-test code untouched).
- Fix, tests only: `closeAtEnd(t, c io.Closer)` (`server_test.go`) closes a session and forgets it; `sharedCatalog(t)` loads the real catalog once per run instead of 1989 times (23 non-integration call sites). New `scripts/race-memory.sh`: builds the race binary, runs one process, prints the peak, under a PID-based guard.
- Docs: `CONTRIBUTING.md`, `docs/development/checks.md` ("Memory of the race suite": numbers, cause, how to measure, what to do when it grows), `docs/INDEX.md`, `ROADMAP.md` M8 row, `.claude/rules/testing.md` (one bullet).

## Decisions & deviations
- **Outcome A**, so no multi-process procedure; the done command stays `go test -race ./...`.
- **Guard.** Every full-package or `go test -race ./...` run was guarded: base non-race and race (the guard fired, recorded above), the fix runs, the five final runs, `go test -race -count=1 ./...` (tree-sum guard over `go test` and children, peak 2594 MiB first run, 2245 MiB last), instrumented non-race runs of the unfixed code (limits 2500 to 5000 MiB; the guard fired on all seven unfixed full-package runs, as intended). Two kinds of small probe ran without the guard because they start at most 120 servers each: `TestZZCatalogLoadCost` (10 loads, race and non-race) and the `TestZZRetain*` probes. None ran beside containers or another test run (`docker ps` empty). All instrumentation (`zz_tmp_*`, counters in `catalog.go`, `server.go`, `leak_test.go`) was temporary, outside the commits, and restored with `git checkout` before committing.
- **`scripts/race-memory.sh` added** although outcome A does not require a script: the ticket asks for "the command that measures it" in the docs, and the only safe way to run it on a small machine is guarded (`ulimit -v` cannot guard a race binary). It is not CI and asserts nothing; its exit code is the tests' (3 when the guard fires). Tested: guard fires (`exit=3`), TERM kills the test process, bad limit → `exit=2`, runs from another directory.
- `sharedCatalog` is package-level lazy state in a test file (`sync.OnceValues(catalog.Load)`); `go.md`'s "no package-level mutable state" is about production code and the value is read-only after the first load (review item dismissed).
- The 6.5 GB and 15-minute timeout of the ticket are the reporter's figures; I measured 5000 MiB (guard limit) and did not run to a timeout. The docs say "as reported".
- The package has 536 top-level names by `-test.list` (fuzz targets included), not "about 400".
- `git stash` was used once in the worktree to build base `-tags` binaries and popped at once (status verified).
- Not done on purpose: the ~40 `t.Cleanup(fake.Close)` stay (the live heap is flat without touching them); the two integration files keep `catalog.Load()`; the macOS/Windows runners were not run (CI will); the Go `testing` behaviour is third-party, not filed.

## Learnings
- Go 1.27.1 `testing`: a finished parallel test stays reachable (parent's `sub` list) with its `t.Cleanup` closures (`runCleanup` does not zero the slice), so closures keep their captures until the run ends; nil the captured variables in the cleanup (`closeAtEnd`). Suggested Applied Learning bullet (not written, CLAUDE.md is off limits to this run): "Parallel tests keep t.Cleanup captures until the run ends; nil them." The rule now lives in `.claude/rules/testing.md`.
- To find who retains memory in a test run: a temporary finalizer counter on the object (set in a copy of the constructor), print live count each second, cross-reference with `-test.v` DONE lines; a heap profile (`pprof.Lookup("heap")` written from an `init` goroutine) names the allocator, not the retainer.
- `pgrep -f race.test` matches the shell that runs it; check children by PID (`pgrep -P`).
- The shell `PATH` has no Go; use the toolchain path above.
