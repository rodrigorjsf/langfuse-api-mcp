## What was built
- A process-level trust proof in `cmd/langfuse-mcp/trustproof_test.go`. The test binary re-executes itself as a **probe child**, selected by `LANGFUSE_MCP_TEST_PROBE`, a JSON map of target name to host:port. The child starts exactly like the executable (`start()`), then runs a TLS handshake with each local target through the executable's own trust pool. It prints JSON on stdout: which of `SSL_CERT_FILE`/`SSL_CERT_DIR` are still set, and the result of each handshake.
- `main()` now only calls `start()`. `start()` captures the ambient CA variables in its first statement, then calls `run()`, which now returns the `trust.Pool`.
- CI (`.github/workflows/ci.yml`, `check` job):
  1. Generates a throwaway "OS" test CA with `go run ./scripts/gen-os-test-ca "$RUNNER_TEMP/os-test-ca"`.
  2. Installs it into the system trust store: Linux `update-ca-certificates`, macOS `security add-trusted-cert` into the System keychain, Windows `certutil -addstore -f Root`.
  3. Runs the tests with `LANGFUSE_MCP_TEST_OS_CA_DIR` set.
- README "For contributors" explains that the proof runs only in CI and that the test CA must never be installed locally.

## Decisions & deviations
- The probe enters through `start()`, not `main()`, because `main()` discards the pool and go.md forbids package-level mutable state, so no test hook exists. The guard therefore covers `start()` and every package init. `main()` itself is one call, and its comment says "Nothing may run here before start".
- The OS test CA is generated at CI time by a Go program in `scripts/gen-os-test-ca/` (WHAT/WHY/WHEN/HOW header), not openssl, so it behaves the same on all three runners. It is built by `go build ./...` and linted. No CA key is committed.
- The OS-store test skips locally and fails in CI when the CA directory is missing (`CI=true`).
- A control case was added beyond the ticket, taken from the prototype's `child-late` mode. It shows the guard has teeth on each OS.
