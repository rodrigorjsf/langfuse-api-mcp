## What was built
- Every write body schema is compiled once at catalog load (jsonschema-go, JSON Schema 2020-12); a schema that does not compile fails the load naming the operation.
- `CheckBody` runs the existing object/size/depth gate first, then full schema validation. A failing body is refused with `invalid_argument`: `invalid body: at /dataType: fails schema keyword "enum"` (root: `at the body root`). The location is a JSON Pointer built only from schema property names and array indexes (a caller's unknown key is never named); no value is ever echoed.
- For anyOf/oneOf failures the explanation descends into the one type-compatible alternative, else the strictly best-ranked one (deeper location; present-but-wrong beats missing), else reports the combinator.
- In write mode `describe_operation` returns `destructive` (bool) and, for an operation with a body, `body: {required, schema}`; text shows `Destructive: ...` and `Body (...), as JSON Schema 2020-12. <third-party framing>` + the schema JSON. Output schema describes both. Read mode output unchanged.
- `execute_write` description and body refusal hint point to `describe_operation` for the body schema.

## Decisions & deviations
- The embedded catalog has no body schema with `additionalProperties:false`, `minimum`/`maximum`, `minLength`/`maxLength` or `pattern` (verified by walking it). The server has no catalog injection, so those cases are proven at the catalog seam with literal schemas; the server seam proves the same refusal path with real operations (type, enum, required, oneOf, nested array item). Recorded in README ("no in-scope schema does today, so Langfuse decides about them"), security.md and the ticket comment.
- Unknown keys are refused only where the schema forbids them (spec wording), not everywhere: Langfuse schemas are open (metadata etc.).
- jsonschema-go error texts quote values, so they are never surfaced; `explain` rebuilds location + keyword by probing single-keyword subschemas. On refusal only it compiles subschemas, cached per refusal (60k-item array refusal ~50 ms, from ~400 ms uncached; measured with a throwaway benchmark).
- `format` (date-time, double) is not enforced: jsonschema-go treats it as annotation, per 2020-12 default.
- `destructive` text says execute_write refuses destructive operations with `confirmation_unavailable` (slice 3 must reword it and the output-schema description once confirmation ships).
- Kept `expectsObject` before schema validation for its clearer message.
- Implementation of compile-at-load preceded its test in one slice (test written right after, verified meaningful: an invalid pattern/ref fails the load).
- No advisor/rubber-duck pass, per implementer rules.
