## Decisions & deviations
- The script is named `check-docs.py`, not `check-security-mapping.py`, so that #157 (T11) can add the README `Planned` rule to the same check. This ticket leaves the README rule to #157.
- Status cell format: `<status>: <detail>`. The status word may be in backticks, and test names must be in backticks. A `planned` link is `#N` or `/issues/N`. The milestone is not checked, because the check is offline per the spec. #156 checks it by hand.
- The known test set is every `func Test*`/`Fuzz*` in any `*_test.go`, including build-tagged integration tests, plus `def test_*` in `scripts/test_*.py`. Node tests (`shim.test.mjs`) are not recognised.
- A row carries only one status, so rows were split where parts differ. The HTTP-token parts moved into the MCP07 row (planned #160), and the supply-chain tooling row (tested) is separate from the signing and provenance row (planned #150).
- L51 (MCP03, static tool names plus signing) stays wholly `planned: #150`, as the ticket asks, even though its static-names part holds today.
- L64 (ASI06–10) and the "every slice" process rule are `accepted-risk`, with reasons.
- The README "Security model" and "For contributors" sections describe the check. `.claude/rules/security.md` gains a "Mapping" paragraph. ROADMAP links #160.
