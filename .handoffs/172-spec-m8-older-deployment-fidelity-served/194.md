## What was built
`describe_operation` now gives a fixed `guidance` on `fields` for all seven operations that take it: the six that had none (`observations_getMany`, `trace_get`, `scores_get-many`, `scoresV3_getManyV3`, `experiments_list`, `experiments_listItems`) and `trace_list`, whose text is byte-identical to #178. Each text names the field groups, what comes back without `fields` and what to know to use it, and appears only on a deployment whose version serves `fields` on that operation. The truncation hint, the hint of `response_too_large` and the hint of a `timeout` or `canceled` call name the same groups ("fewer field groups in fields (core, io, ...)"), from one compiled list, and mention `fields` for no operation that lacks it on the deployment, nor for `get_trace_tree` (it takes no such argument). The values come from the Langfuse release specs, read for every release from v3.73.0 to v4.56.0, and are recorded in `docs/research/langfuse.md` section 1.5 (which gained the rows for `GET /v2/scores` and `GET /traces/{traceId}`).

## Decisions & deviations
- One compiled source: `internal/catalog/fieldgroups.go` holds a `fieldsGuide` per operation (lead, groups with optional `holds`/`since`, tail). `guidance()` and `hint()` both render the same `groups`; `Operation.FieldGroups()` returns the hint list and is empty unless the deployment serves `fields` on the operation. `staticGuidance` is built from it by `buildStaticGuidance`, so `trace_list` is no longer a hand-written constant (its text is byte-identical, pinned by the unchanged test literal).
- Hint wording: "fewer field groups in fields (<groups>)" replaces "request fewer fields" / "fewer fields" in all three hints; shared by `sanitize.Remedies.FieldsWay` and `sanitize.JoinWays`. `Remedies.Fields bool` became `Remedies.FieldGroups string` (review finding: the name said nothing about text).
- Facts that differ from the triage table: (1) `observations_getMany` `trace_context` arrived in 3.175.0, not at 3.141.0, so it is named with that release; (2) `scoresV3_getManyV3`: `core` was listed as an allowed value in the specs of 3.180.0 and 3.181.0 and in no later one; the text never suggests it and says the core fields are always returned; the route first appears in a spec at 3.180.0 though the catalog floor (documented) is 3.179.0, and the specs before 3.182.0 do not say what a group adds, so the guidance gives names only; (3) the research row `core (always)` for `GET /v3/scores` was wrong and is corrected; (4) the claim "a field of a group not asked for is absent, not null" is not in the specs and has exceptions (`modelId` and the prices are present as null), so the observations text says "ask for every group that holds a field you need: with core alone a row has no name" instead (review finding).
- `fields=core` on `/v3/scores` was not run live (no pinned 4.x stack was up); the research row says so.
- `get_trace_tree` takes no `fields` argument, so its failure hints see the operation it reads through `Operation.WithoutQueryParam("fields")` (catalog). Its own too-large texts (#193) are unchanged. Until #203 lands its timeout hint still names a window and a limit the tool lacks; this ticket only removes `fields`.
- The words "a shorter time window" and "a lower limit" are untouched (#203): `trace_get` on 3.80.0 now reads "narrow the query: a shorter time window or a lower limit", which is still wrong advice and is pinned as a literal that #203 will change.
- `skills/langfuse-api-mcp/references/errors.md` keeps its generic "fewer fields" lines on purpose (client guidance for every operation; #203's triage note decides the same for its own words).
- Unverified, left alone: the `trace_list` sentence "a group left out comes back empty" (#178) is in the spec from 3.110.0; the specs 3.73.0 to 3.109.x say only "if not provided, all fields are included". The ticket says trace_list's text is unchanged, and I could not run a 3.x deployment here; the 3.80.0 exit campaign (#184) will read it.

## Learnings
- The Go toolchain is not on PATH: `export GOROOT=$HOME/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-amd64; export PATH=$GOROOT/bin:$HOME/go/bin:$PATH`.
- `go test -race ./...` still ends in a timeout kill on this machine (#201); run `internal/server` as `go test -race -c`, `-test.list`, then 12 round-robin `-test.run` processes with GOGC=50 and a resident-set watcher (a 40-line Python script did it in 4 minutes).
- The release specs are fetchable one by one: `https://raw.githubusercontent.com/langfuse/langfuse/<tag>/web/public/generated/api/openapi.yml` (296 tags from v3.73.0 took about two minutes with `xargs -P 10`); a blobless clone is not needed to read a parameter's description over time.
- The Bash tool expands a typed backslash-u escape in a heredoc into the real character, so a Go test string with U+202E or U+200B lands as a hidden character and staticcheck ST1018 fails; write the escape with `chr(92)` from Python and `grep -P` the files afterwards (the #178 learning, met again).
- A backgrounded `( ... ) &` inside a tool command is killed when the command returns; use `run_in_background`.
