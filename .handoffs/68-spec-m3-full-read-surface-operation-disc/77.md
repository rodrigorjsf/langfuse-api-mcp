## What was built
The `refusedURL` test helper (`internal/server/network_test.go`) no longer closes a listener and hands out its freed port. It keeps a loopback listener open, dials it once, and returns the local port of that open client connection. Nothing listens on that port, so a connect is still genuinely refused (same `network_error`, retryable contract), and no other test's server can bind it until the test ends (both are released in `t.Cleanup`). No production code changed.

## Decisions & deviations
- Tried the brief's "accept and reset at once" option first (reusing `resettingListener`). Under `-race -count=20` load it made a reset host come back as `internal_error` instead of `network_error` (reachability and network tests failed), which would change the error class. Dropped it for a true refusal that still owns the port: the port is the local end of an open dialed connection. Go does not set SO_REUSEADDR on dialed sockets, so `Listen`/autobind cannot take it (Linux verified by test; macOS/Windows reasoned by the Standards reviewer, test binaries cross-compile for both).
- Kept all test names and the `refusedURL` name; only the helper body changed.
- The reset-classified-as-internal_error observation is production behaviour (out of scope) → filed #91.
