# Handoff — #145: Claude Code fails to connect with duplicate "initialize" when startup profile detection takes about 4 s

Status: DONE

## What was built
The stdio transport no longer offers MCP protocol 2026-07-28 (candidate B of the spec). When Langfuse answers the startup probes slowly, Claude Code's `server/discover` probe and the legacy `initialize` it sends after 3 s both wait in the pipe. go-sdk v1.8.0 used to store the probe's parameters on the session and then refuse the `initialize` as a duplicate. Now the probe is answered with `supportedVersions` lacking 2026-07-28 and stores nothing, so the `initialize` succeeds on 2025-11-25 and `tools/list` answers. Every stdio client now negotiates through `initialize`. Destructive-call confirmation goes through the SDK's older-protocol `elicitation/create` path, which was verified live with Claude Code. The draft upstream go-sdk report (option D) is in the raw record. It has not been posted.

## Decisions & deviations
- **The probe is answered, not refused.** The fix uses `mcp.ProtocolVersionSupporter` on a wrapped `mcp.StdioTransport`. go-sdk then answers `server/discover` with the transport's versions (no 2026-07-28) and stores no session state. Claude Code falls back to `initialize`, as captures 3 and 4 show. The literal AC wording ("the probe is refused") would need `ServerOptions.SupportedProtocolVersions`. That option is server-wide and would break the in-memory 2026-07-28 confirmation tests the AC requires to stay green, so it was not used. The outcome B needs is proven. The new test accepts either an error or an answer without 2026-07-28, and it goes red through the `initialize` failure.
- **Residual.** A client that ignores `supportedVersions` can still send sessionless 2026-07-28 requests over stdio, and the SDK checks those against the server's full version list. No known host does this. The tool set stays fixed either way.
- **Claude Code 2.1.284 already recovers without the fix.** It re-probes after the refused `initialize` (capture 2). 2.1.283 is no longer installed, so the post-fix live proof is on 2.1.284 only. The process test is what isolates the fix.
- ADR-0012's startup-budget amendment claimed detection "never holds up the host's `initialize`". A short correcting amendment was added. It is not a new ADR, and the startup order is unchanged.
- The README Troubleshooting row for #145 is left to T11 (#157), per spec #150 story 31. The `docs/research/security.md` mapping row for the new stdio control is left to T9 (#155), which adds a row for every control of `.claude/rules/security.md` the mapping lacks.
- No advisor or rubber-duck pass was run (agent hard rules).
