## What was built
- `search_operations` now adds a static **trace reads hint** when the query matches nothing, or when it holds the word `trace`/`traces` (case-insensitive, whole word, split on non-letters/digits).
- The hint names how trace data is read: `get_trace_tree` for one trace, `execute_read` with `observations_getMany` for filtered lists, and `execute_read` with `metrics_metrics` for aggregates such as cost per day.
- Each item appears only when the deployment offers it: `get_trace_tree` only when registered (v4 read family on); the operations only when the resolved catalog lists them. When none is offered, the hint is absent (for example on 3.x legacy).
- The hint is in a new optional structured field `hint`, declared in the output schema, and ends the text result. The index lines are unchanged.

## Decisions & deviations
- The hint also goes into the text content, not only the structured `hint` field. Models read the text, and the spec forbids only the index lines.
- The hint ends with "describe_operation returns an operation's parameters.", a static nudge toward the next step.
- The term "route" is avoided in the text and identifiers: CONTEXT.md lists it under Avoid. The concept is called the "trace reads hint". It was not added to CONTEXT.md, because it is a hint, not a domain term.
- `discovery` gained a `traceTree bool`: whether `get_trace_tree` is registered, from `profile.On(catalog.V4ReadFamily)`. It is shared with the registration in `server.New`.
- Word matching splits on any character that is not a letter or digit, so `trace_list` and `trace-id` trigger the hint and `traceId` does not.
