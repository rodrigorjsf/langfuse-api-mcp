## What was built
The result size cap (`LANGFUSE_MCP_MAX_RESULT_BYTES`) now bounds `search_operations` and `describe_operation` too: neither the text content nor the structured content of a result is longer than the cap. A body schema that does not fit loses only its `description` and `title` annotations (`describe_operation`, write mode); if it still does not fit, the schema is left out whole and `body` keeps `required`. An operation index that does not fit keeps its leading entries, cut at an entry boundary, with `count` still the number of matches. Both say `truncated: true` with a static hint. At the default cap every result is byte-for-byte what it was. The two largest write operations (`unstable_evaluationRules_create` 37 KB, `_update` 17 KB) and the write-mode index (18.8 KB structured) now fit 16384 bytes.

## Decisions & deviations
- Reduction lives in `catalog.RequestBody.SchemaWithoutAnnotations()` (pure; walks only JSON Schema 2020-12 subschema positions, so property names and data keywords are safe; same decode/marshal path as `cleanSchema`, so output is compact, sorted, numbers exact). `Schema` and the compiled schema are untouched, so `CheckBody` is unchanged.
- New optional members: `truncated` and `hint` on both tools; `body.schema` is no longer required in the `describe_operation` output schema (absent only in the whole-schema fallback). For `search_operations`, `hint` is the existing trace-reads hint; when a trace query is also cut the two are joined (`trace hint + " " + truncated hint`). `count` now means "matched"; text header becomes `N operations match; the first M are listed`.
- Measure = larger of text bytes and structured-content bytes (as the client receives them).
- Deviation (spec says "with a catalog fixture"): `catalog` exports only `Load()`, so the whole-schema fallback is tested through the server seam with a cap of 4096 on the shipped catalog (the server option accepts any cap; only the config enforces the 16384 floor). Same code path. If `WithMaxResultBytes` ever enforces the floor, that test needs an exported custom loader.
- Not guaranteed (documented in the `discovery.maxResultBytes` comment): a description with no body to reduce, a schema-less description or a zero-entry index is returned even if over a cap below the operator's minimum; unreachable with the shipped catalog (the walk test proves every write operation).
- `CONTEXT.md` **Result size cap** got one clause (a discovery result is reduced by its shape): both reviewers read the term's mechanism sentence as stale. A swallowed reduction error falls back to leaving the schema out, with a comment saying why.

## Learnings
- `go test -race ./internal/server/` in one process exhausts 8 GB RAM and swap (looks like a 15-minute timeout); run it in chunks: `new.test -test.list '.*'`, then `-test.run '^(a|b|…)$'` per round-robin chunk, `GOGC=50`.
- `pkill -f <name>` in a script whose own command line contains `<name>` kills the shell; use `pkill -f "[n]ame"`.
- go toolchain is not on PATH here; use `GOROOT=~/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-amd64`, `GOTOOLCHAIN=local`.
