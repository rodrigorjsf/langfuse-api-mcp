Full risk→control mapping with sources: `docs/research/security.md`. Cite OWASP IDs **with the year** (IDs were renumbered: Excessive Agency = LLM06:2025 = LLM03:2026). Run `/security-review` before merging anything touching the areas below. **Credentials**
- Langfuse keys come only from the server's environment/config — never from tool arguments, never forwarded from the MCP client (no token passthrough). Langfuse keys cannot be read-only, so the server is the only write gate for calls through the server; keys in the agent's own environment bypass it (#146).
- The config file (ADR-0011) must never hold keys: reject `LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY` found there (any spelling, after `export` and any blanks, #156) with a startup error; tests prove it.
- An unknown config-file key only draws a startup warning naming file, line and key (escaped, cut to 64 runes), never its value (#26); tests prove it.
- Redact `Authorization`, `sk-lf-…`, `pk-lf-…`, the HTTP bearer token and proxy credentials (`user:password@` in a proxy URL; used only for Basic proxy auth, logged as `scheme://host:port`) from logs, errors, hints, the audit line and tool output. A startup error for an invalid proxy value names the variable and its source, never the value.
- Header credentials inside Langfuse data (#180): `sanitize.Redactor.Redact` also replaces the token of `Authorization: <scheme> <token>` and of `Bearer <token>` and keeps the rest (`Authorization: Bearer [REDACTED]`). The keywords match in any case at the start of a word (a hyphen starts one: `Proxy-Authorization` matches); blanks (spaces or tabs) may sit around the colon, and at least one blank sits before the token; a scheme is a letter, then letters, digits and `_ . + -`. A token is a run of at least 16 printable ASCII characters other than space, `"`, `'`, `` ` `` and `\` (`minTokenLength`, kept above the 10 characters of `[REDACTED]` so redacting twice changes nothing); it ends at the first other character, so a closing quote or a JSON escape ends it, and a credential holding such a character (or a non-ASCII one) is redacted only up to it, if that part has 16 characters. The shape is all it checks: a long word or a URL right after `Bearer`, or after `Authorization: <word>`, is taken for a token. Not redacted: a shorter token, prose with short words after the keywords, `Authorization` with no scheme, the value of a JSON header map under an `Authorization` key unless it starts with `Bearer` (#196), and any other secret format. It runs wherever a key is redacted, always before a cut: every payload string and key (before clipping), Langfuse error text (before 500 runes), the operation ID, parameter name and argument name an error echoes (before 64 bytes), the body summary of a confirmation (before 300 runes), the audit line, and a last pass over each result's JSON text. Invisible and control characters are stripped before matching, so a token split by them is found, and are gone from a text that held a secret; tests prove each.
- After startup the key pair travels only as `langfuse.KeyPair`, which renders `[REDACTED]` in fmt, JSON and slog; never copy the keys into plain `string` fields.

**Write gating** (ADR-0003 and its amendment)
- `execute_read` accepts GET operation IDs only. `execute_write` is not registered unless `LANGFUSE_MCP_ALLOW_WRITES=true` (exactly `true`/`false`, environment or config file, environment wins; any other value stops startup naming the variable and its source, never the value). Tests must prove both.
- The tool set is fixed at startup; it never changes per request or per client.
- While write mode is off no tool tells a write operation ID from one that is in no release (#192): `execute_read` and `describe_operation` answer it `operation_not_found` in the words and with the hint of an unknown ID, naming no HTTP method, echoed only redacted, stripped, quoted and cut to 64 bytes, and sending nothing. In write mode `execute_read` keeps `invalid_argument`, naming the method and pointing to `execute_write`. An excluded operation keeps its answer. The tool descriptions and schemas are the same in both modes, so they name no write operation ID. Tests prove each, with every write operation of the catalog walked.
- `execute_write` (#110): an excluded, unknown or read `operationId` is `operation_not_found` (an unavailable write `operationId`, #174, is `operation_unavailable`; each tool answers `operation_unavailable` only about the operations it runs, `describe_operation` about both), echoed only redacted and cut to 64 bytes; path and query parameters get the `execute_read` checks; the body must be a JSON object where the schema expects one, at most 256 KiB compacted and 32 levels deep, and absent where the operation takes none, refused with `invalid_argument` naming the rule, never the value, before any request; then (#112) it is validated against the operation's JSON Schema 2020-12, compiled once at catalog load, and a failure is refused with `invalid_argument` naming only the JSON location (built from schema property names and array indexes, never a caller's key) and the failed keyword, never a value; unknown keys are refused where the schema forbids them. In write mode `describe_operation` returns the body schema (stripped at load, framed as third-party text), a `destructive` flag and, for `comments_create` and `scores_create` only, a static `body.guidance` (#192), and `search_operations` gives every write line its HTTP method and `destructive`, the value `describe_operation` returns (#192). Every destructive operation (DELETE, PUT, PATCH) runs only after the user confirms that exact call (#113, ADR-0003 amendment): after its parameter and body checks, the server asks through form elicitation with a multi round-trip request (`InputRequests` + a `RequestState`; older-protocol clients go through the SDK middleware, same handler path). The state is `<expiryUnix>.` + base64url(HMAC-SHA256(key, `<expiryUnix>|<operationId>|` + the checked request re-encoded deterministically)), the key 32 `crypto/rand` bytes drawn at startup, never logged or persisted; it expires after 5 minutes and is compared with `hmac.Equal`. Fail-closed, nothing sent: no form elicitation (per-request capabilities) → `confirmation_unavailable`; decline or cancel → `confirmation_declined`; an accept without a valid state (sent on the first call, other arguments, forged, corrupted, expired, another process's key) → `confirmation_invalid`. No setting skips it. The confirmation text names the operation ID, method, path and query parameters and a body summary cut at 300 runes (saying so, with the body size in bytes), the trace ID count for `trace_deleteMultiple`; every argument-derived string is stripped of control, invisible and bidi characters, redacted and shown quoted, markup as text (not escaped: the elicitation message is plain text per MCP, so markup rendering is the client's). Replay of the identical call within the expiry is not prevented (every confirmed method is idempotent). POST creates run without a server confirmation. A write is never retried. Its audit line is logged at `Warn` with `confirmation` and never the body. Excluded from the catalog: `media_getUploadUrl`, `media_patch`, `llmConnections_upsert`, `blobStorageIntegrations_upsertBlobStorageIntegration`; a catalog test fails on any in-scope write body property whose name contains `secret`, `password` or `accessKey` (ADR-0004 amendment). Tests prove each.

**Every slice: prompt injection + dangerous parameters** (LLM01:2025/2026, MCP05/MCP06:2025)
- Any spec, ticket or change that adds or alters a tool, operation, parameter, workflow, or write path lists in its acceptance criteria (a) its prompt-injection cases — instructions, hidden/bidi characters and markup inside Langfuse payloads, echoed input in error text — and (b) its dangerous-parameter cases — unknown params, URLs/schemes/hosts, traversal, control characters, wrong types, out-of-range limits, oversized filters or query JSON.
- Each case is proven by a test at the seam. A missing case is a Spec-axis finding in `/code-review`; a case that cannot be closed now becomes a `/follow-up-issue`, never a silent gap.

**Requests to Langfuse** (SSRF / injection)
- Base URL comes only from operator config; `https` required except loopback hosts.
- Model input selects an operation ID + params; every value is checked against the operation schema (type, enum, and the spec-given `minimum`/`maximum` and `minLength`/`maxLength` in runes, after the list `limit` check so `limit` keeps its own error and hint; a schema without a type bounds a JSON number by value and a string by length, #83; the refusal names the bound, never the value, #80) and unknown params are rejected; reject absolute URLs, schemes, hosts, `//`, `.`/`..` segments, `/` and `\` in path params; percent-encode path params. `/` is accepted only for a Folder name on the static, fail-closed allow-list of `(operationId, parameter)` in `internal/catalog` (`prompts_get`/`promptName`, `datasets_get`/`datasetName`, `datasets_getRuns`/`datasetName`, `datasets_getRun`/`datasetName`; writes, #113: `prompts_delete`/`promptName`, `promptVersion_update`/`name` and, before 3.18.0, `promptVersion_update`/`promptName`, `datasets_deleteRun`/`datasetName`), sent as `%2F`, with no empty, `.` or `..` segment; a refusal message never contains the value (#33). The text of a value is checked before any request (#179): a control or invisible character (the set `sanitize.Text` strips from a payload, plus tab, line feed and carriage return; `TestAPathParameterRefusesExactlyTheCharactersTheSanitizerStrips` pins the two) in a path parameter is refused, never removed, so no ID the caller did not send is looked up (a Folder name on the allow-list included); in a query parameter value, a list item included, it is refused too (tab, line feed and carriage return are control characters there as well; only a `filter`, a JSON text that Langfuse parses, may hold them), and so is one in a metrics `query` once decoded, written as itself or as a JSON escape; the text of a `filter` is checked as text, and a JSON escape inside it is Langfuse's to decode (#195); `page` below 1 is refused, the refusal naming its minimum; a parameter whose schema says `date-time` must be an RFC 3339 timestamp (date, `T`, time with seconds, optional fraction, `Z` or an offset; no looser form), the refusal naming the parameter and the format; no refusal holds the value; `orderBy` stays checked by Langfuse; tests prove each.
- Custom `CheckRedirect`: refuse any redirect that changes scheme, host, or port (Go forwards `Authorization` on same-host and subdomain redirects).
- Served parameters (#173, ADR-0012 amendment): an operation offers, and `execute_read`/`execute_write` accept, only the parameters the deployment's version serves; the catalog resolves them at startup from each parameter's `x-introduced`/`x-removed`, and with no detected version serves the newest release's, which the startup log says. A parameter of the operation that the version does not serve is refused with `invalid_argument` before any request: the message names the parameter (a catalog name, never the caller's text), the operation, the deployment's plain version and the release range from the catalog, never the value; the hint is static text and names only the way of paging the operation has, `page`, `cursor` from `meta.cursor` or neither, from its served parameters (#193). A name that is no parameter of the operation in any release keeps the unknown-parameter refusal, the name echoed only redacted and cut to 64 bytes; a served parameter's value gets every check below. Tests prove it at the catalog seam (both executors share `Operation.Request` and `parametersHintFor`) and at the `execute_read` seam; no write operation carries a ranged parameter today, so `execute_write` has no test of its own for it.
- Filter scan (#183, ADR-0010 and ADR-0012 amendments): where the deployment's version does not serve `traceId` of `scores_get-many` or `level` of `legacy_observationsV1_getMany` (the closed list `catalog.ScannedFilters`, exactly two `(operation, parameter, row field)` pairs; whether a pair qualifies is never decided from a payload), `execute_read` reads the list without the filter and keeps the rows whose field equals the value, instead of refusing it. The call is checked as if the deployment served the filter (`Operation.Scan`), so the value gets the type, enum, bounds and control and invisible character checks of a sent one, before any request; a `page` together with the filter is `invalid_argument`; a JSON null filter is no filter. The scan (`internal/workflows/filterscan.go`) reads from page 1 at `MaxLimit` rows a page whatever `limit` the call names (checked, then replaced) for at most `MaxScanPages` (10) pages, so no argument raises the page limit, through the one client (rate limit, concurrency cap, retries), and the audit line counts every request. Each page is sanitized and redacted before its rows are compared, so a row is matched as the agent would read it and comes back only as data inside the envelope, through clipping and the result size cap (the truncation hint names a time window, never a lower `limit` or paging). The result is page-shaped, `meta.filterScan` holds static text and numbers (`appliedBy`, the catalog's parameter and row field name, `complete`, `pagesRead`, `rowsRead`, `rowsExist`, `rowsMatched`), never the value or payload text, and none of Langfuse's pagination metadata. A failed page, or an answer that is not a page of row objects, ends the scan with its tool error and no rows. The scan ends where `meta.totalPages` says the list ends, else at the first empty page (never at a short one, which a smaller page size would also give), so a partial answer is never called complete. The rows are compared after redaction and the value as it was sent, so a value that holds a Langfuse key or a bearer token matches nothing. `describe_operation` still lists only the served parameters, so it does not show the two scanned filters (#199). Tests prove each.
- Timeouts, concurrency cap and rate limit (one shared per process, retries included, set only by `LANGFUSE_MCP_RATE_LIMIT`/`LANGFUSE_MCP_MAX_CONCURRENCY`; unset, the rate limit defaults by host: 30/min on an exact Cloud host, 1000 elsewhere, an explicit value always wins, #47), max response bytes read, max tool-result bytes returned (the result size cap: clip the largest string values (#177: each keeps its start and ends in the static marker `… [clipped]`; the floor is 128 bytes; a result that fits is untouched), then leave out rows of the payload's list of rows (a page's `data`, or the longest list of an object) at a row boundary only if that is not enough, never clipping a continuation cursor, saying `truncated` with a static hint built from the parameters the operation takes, never from payload text; clipping runs after sanitizing and redaction; default 64 KiB, set only by `LANGFUSE_MCP_MAX_RESULT_BYTES`, an integer 16384 to 1048576 from the environment or the config file, environment wins; any other value stops startup naming the variable and its source, never the value; no tool argument reaches it, and a host may have its own lower limit for showing a result; applies to every tool result, workflow tools included; the discovery tools return catalog text, which is reduced by shape and never cut at a byte, #190 (see "Discovery" below); tests prove it); default and cap `limit` on list operations (the hint of a `limit` out of range, that of a `response_too_large` and the truncation hint of a page that lost rows name only the way of paging the operation has, static text, catalog parameter names and numbers, never a value, #193), and `config.row_limit` in the metrics `query` JSON (default 100, refuse outside 1..1000; the JSON is bounded to 16 KiB and depth 10, known top-level keys and their types only, re-encoded before it is sent). The metrics query guidance `describe_operation` gives on the `query` parameter of `metrics_metrics` and of `legacy_metricsV1_metrics` and the hint of a refused metrics query are static text whose key list is the validator's own, and never contain the query (#104, #178); tests prove it.

**Tool results** (LLM01:2025/2026, MCP06:2025)
- Langfuse payloads are untrusted data: wrap them in a labelled envelope; strip invisible/bidi Unicode (U+E0000–E007F, zero-width, bidi overrides, variation selectors and other default-ignorable code points, #156) and control chars; a terminal escape sequence goes whole, not with its escape character alone (#193): wherever the server strips control characters from Langfuse data (`sanitize.Text` for every payload string and key, the audit line and a confirmation, `sanitize.Message` for error text taken from Langfuse), a CSI (ESC `[` or U+009B, parameter and intermediate bytes, one final byte; the U+009B form, the only one that can stand raw in the JSON text of a result, also ends its scan at a quote or a backslash, so it never takes the quote or the backslash of a JSON string) and an OSC (ESC `]` up to BEL or ESC `\`, an OSC 8 hyperlink with its URL) are removed with the rest of the sequence, by a scan of at most `sanitize.MaxEscapeSequenceRunes` (256) characters from the escape character; an escape character that starts no complete sequence within them goes alone and the text after it stays, so no payload makes the sanitizer drop more than that; text with no escape character before it (`[31m`) is never changed; each JSON string is cleaned alone; the removal runs before redaction and clipping, so a key behind or split by a sequence is still redacted and the cap counts the cleaned text (the embedded OpenAPI text of the catalog is not Langfuse data and keeps its own load-time stripping); tests prove each; never render HTML/Markdown from them; never echo them unescaped into error text. A proxy's CONNECT answer (status reason, body) is untrusted too: it is dropped, never echoed into an error, hint or audit line (#32).
- Tool names/descriptions are static strings compiled into the binary — never built from API data.
- Discovery (`search_operations`, `describe_operation`, ADR-0002 amendment): operation tags and description lines are stripped of invisible/bidi and control characters when the catalog loads, a Markdown link in a line keeps only its text, bold markers (`**`, `__`) are removed, and a line is cut at 200 runes (tests prove it, #79, #82); instruction-like text cannot be detected, so both tools' text and output schemas frame the lines as third-party text from the Langfuse OpenAPI spec, data and not instructions (#82); every string of a write operation's request body schema, keys included, is stripped of invisible/bidi and control characters at load, tab and line breaks kept (#81, test-proven; no link reduction or length cut); the result size cap bounds both tools' results, text content and structured content each (#190): `describe_operation` leaves the `description` and `title` annotations (the keywords of a schema, not a property named so, and nothing inside `const`, `enum`, `default` or `examples`) out of a body schema that does not fit, the reduced schema accepts and refuses the bodies the full one does, and if it still does not fit the schema is left out whole with `body.required` kept; `search_operations` keeps the leading entries of an operation index that does not fit, at an entry boundary, with `count` the number of matches; both say `truncated` with a static hint (one for each reduction, the trace reads hint first in a cut trace query) that holds neither the query, the `operationId` nor any catalog text; the reduction only removes text from catalog text already cleaned at load, keeps the notes that frame the lines and the body schema as third-party text, takes no argument, is bounded by the catalog's own schema size and depth, and runs after the `query` and `operationId` checks, whose refusals are unchanged; `execute_write` validates a body against the full schema at every cap; a test walks every write operation of the union catalog at the smallest cap and fails naming the operation if its reduced description does not fit (tests prove each); `query` and `operationId` over 128 runes or holding a control or invisible character are refused with `invalid_argument`; the query is never echoed, and the trace reads hint of `search_operations` (#100) is static text naming only the tools and operations the resolved catalog and tool set offer, given only when the query holds the word `trace` or `traces` (#114); the static per-parameter guidance of `describe_operation` covers the `metrics_metrics` and `legacy_metricsV1_metrics` `query` (#104, #178; both built from the validator's own key list), the `prompts_list` `tag` and `filter` parameters, naming `tag` as the tag filter and `filter` as not (#141; `filter` stays in the catalog and is still sent), the `prompts_get` `label` and `version` (neither means `production`; `latest` names the newest) and the `trace_list` `fields` values (#178; only on a deployment that serves `fields`), is compiled into the binary, holds no caller input and no Langfuse data, and no other parameter of any operation carries guidance (tests prove it); the static body guidance (#192; `Catalog.BodyGuidance`) covers `comments_create` (its `projectId` is the ID of the project the server's keys belong to, which `projects_get` returns, named only when the resolved catalog offers it) and `scores_create` (a score needs exactly one target, `traceId` with an optional `observationId`, `sessionId` or `datasetRunId`, each named only when the body schema has it and the deployment's version has it too, `sessionId` from 3.53.0 and `datasetRunId` from 3.55.0, since the union catalog keeps the newest release's body schema, #202), is compiled into the binary, holds no caller input and no Langfuse data, is kept by every reduction of a result for the size cap, and no other operation's body carries any (tests prove it); the 404 hint of `prompts_get` called with no label and no version names the implicit `production` label from static text, never the prompt name (#178); an unknown, excluded or (write mode off) write `operationId` is `operation_not_found`, echoed only redacted and cut to 64 bytes; an ID of the union catalog that the resolved catalog does not offer is `operation_unavailable` in `describe_operation`, `execute_read` and `execute_write` (#174, ADR-0002 amendment), its message and static hint naming the catalog's own operation ID, the replacement operations the catalog offers and the deployment profile, never the call's text, and a legacy line of the operation index names a preferred operation only when the resolved catalog offers it (tests prove it). `execute_read` echoes an unknown `operationId` only redacted, cut and stripped of control, invisible and bidi characters, under the static hint naming `search_operations` (#36). `get_trace_tree` (#74): a `traceId` over 128 runes or holding a control or invisible character, an `include` value other than `io`/`metadata`, a wrong type or an unknown argument is refused with `invalid_argument` before any Langfuse request, never echoing the value (an unknown argument's name only redacted and cut to 64 bytes); the `traceId` goes to Langfuse only as a query parameter; the tool is registered on every deployment (#175, ADR-0002 amendment): where neither the v4 read family nor the legacy family is on, a call that passed those checks is answered `operation_unavailable` with fixed text (the deployment's version and families, `trace_get` only when the resolved catalog offers it, never the `traceId`) and no request, and the tool set stays fixed at startup and identical for every client; where only the legacy family is on it builds the tree from `legacy_observationsV1_getMany` (#187, ADR-0002 amendment): the `traceId` only as a query parameter, at most 10 pages of 100 (`workflows.MaxLegacyTracePages`, `LegacyTracePageSize`) whatever the call asks, through the one client (rate limit, concurrency cap), each page cleaned and redacted before its rows are read, then `input`, `output` and `metadata` removed from every row by key name at the top level unless `include` asks for them (so a hidden character or escape in a key cannot keep them), every row returned whatever its `id` and `parentObservationId` hold, a failed page ending the call with its tool error and no partial tree, and the hints (the next page number included) static text plus numbers; the trace tree comes back sanitized inside the untrusted-data envelope, its large values clipped and, only if that is not enough, cut at a row boundary at the result size cap. A continuation cursor is opaque Langfuse data (#93): never decoded, handed back only as `data.meta.cursor` inside the envelope (never in a hint or the audit line), and sent back through `execute_read` unchanged as one string query parameter (a non-string `cursor` is refused); tests prove it.

**Build metadata** (#127): the server version in `initialize` and the startup log is the linker-injected one, else the build info's module version only when it is a release tag (`vX.Y.Z` or `vX.Y.Z-pre`, no pseudo-version, no build metadata such as `+dirty`), reported without the `v`; anything else is `0.0.0-dev`, so no other build-metadata string is echoed; tests prove it.

**Transport**
- stdio: logs to stderr only. It offers no protocol from 2026-07-28 (#145), and it reads no byte of stdin until the session has recorded that (#191): go-sdk v1.8.0 starts reading inside `Server.Connect` and records the transport's protocols a few instructions later, so a `server/discover` probe already waiting in the pipe, as Claude Code leaves it during a slow startup, could be answered with 2026-07-28 and stored as the session's `initialize` parameters, and the legacy `initialize` after it refused as a duplicate. A probe therefore never negotiates a session, however early it arrives, and is answered with the older protocols only; a session is negotiated only through the legacy `initialize`; neither the client capabilities of a handshake, nor a probe sent before, between or after the `initialize` messages, nor a second `initialize` change the tool set or the write gate, and a malformed `server/discover` is refused without dropping the connection; tests prove it, with the probe forced to be handled inside the SDK's window. Both workarounds go once go-sdk accepts a legacy `initialize` after a probe and records a transport's protocols before it reads the first message (#162). HTTP (opt-in, **Planned**, #160; stdio is the only transport today): bind 127.0.0.1, require a random ≥256-bit bearer token compared in constant time, validate `Origin` (403 on invalid) and `Host` (loopback only), answer session GET/DELETE with 405.

**TLS** (ADR-0006): system pool + explicit/ambient CAs appended in code; `SSL_CERT_FILE`/`SSL_CERT_DIR` are captured and removed from the environment before anything loads certificates (proven by `TestExecutableTrustsTheOSStoreAndAmbientCAsAtOnce`); `MinVersion` TLS 1.2; no skip-verify option exists.

**Audit**: one structured stderr log line per tool call (tool, operationId, method, status, latency, bytes, requests: the Langfuse requests the call made) — metadata only, never payloads, and the cause of a request that got no answer never holds the request URL or a refused redirect's target (#156); an `execute_write` line is at `Warn` and adds `confirmation` (`not_required`, `requested`, `accepted`, `declined`, `unavailable`, `invalid`).
