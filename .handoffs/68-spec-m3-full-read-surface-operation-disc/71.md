## What was built
The server now embeds the union catalog (ADR-0012), `internal/catalog/spec/langfuse-union-catalog.json`. It replaces the single `langfuse-openapi.json`, which is deleted. The file is generated by `scripts/gen-union-catalog.py` from the OpenAPI spec of 399 release tags from v3.0.0 to v4.46.0 (116 distinct specs, 137 operations, 13 of them excluded by ADR-0004). Each operation carries `x-introduced`, `x-removed` when it left the spec, and `x-family` (legacy, v4 read, experiments). Documented floors win: OTLP 3.22.0, `/v3/scores*` 3.179.0. `catalog.Resolve(Profile)` narrows the union purely, with no I/O. Until detection lands (#72), the server resolves with an unknown version and every family on, so operations only older releases serve (for example `score_get`, removed in 3.53.0) are reachable through `execute_read`. A weekly workflow, `.github/workflows/union-catalog.yml`, regenerates the file and opens a pull request when it changed.

## Decisions & deviations
- **Unknown version, not the newest known version, until #72.** The ticket's "resolves with the newest known version" contradicts its own AC: removed operations are out of range at 4.46.0. So an unknown or unparsable version keeps every range. A known newer version is clamped to the newest known version, as the fixture shows. The consequence was noted on #72: removed operations are visible and 404 on 4.x until detection lands.
- **Below 3.0.0** resolves at the oldest known version (3.0.0) and ignores families. The union knows nothing older, so plain ranges at 2.x would keep nothing.
- **Shared operation IDs.** `promptVersion_update` names two paths with disjoint ranges. The generator refuses overlapping ranges, and resolution keeps the operation introduced last.
- **Legacy family** = deprecated in the newest spec and not removed. `unstable/evaluators*`, which was deprecated and then removed, is range-bounded only.
- **Generator in Python + PyYAML**, the approach proven on the prototype, to avoid adding a Go YAML dependency. The file keeps only what the catalog reads, so request bodies are dropped (#81).
- **Fixture literals are pinned to concrete versions** (3.80.0, 3.225.11, 4.46.0). A regeneration changes only the "newer than known" row, which the regeneration PR updates. The workflow body and the README say so.
- `catalog.Profile` carries Version and Families only. "Known" and "supported" are derived from the version string.
