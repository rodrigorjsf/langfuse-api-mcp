## What was built
With no linker-injected version, the executable now reports the build info's main module version, without the leading `v`, but only when that version is a release tag (`vX.Y.Z` or `vX.Y.Z-pre`, strict SemVer, no build metadata). A pseudo-version (all three Go forms), `(devel)`, an empty version, a `+dirty` version, or any other string reports `0.0.0-dev`. A linker-injected version (release builds, GoReleaser) always wins. So `go install …@v0.1.0` reports `0.1.0`, and a local `go build` in a checkout that is not on a clean tag still reports `0.0.0-dev`. That was checked by hand: the build is stamped `v0.0.0-…+dirty` and `initialize` reports `0.0.0-dev`.

## Decisions & deviations
- `main.version` now defaults to `""`, meaning nothing was injected, instead of `server.DevVersion`. The fallback is decided in `reportedVersion`.
- The pseudo-version pattern is golang.org/x/mod's `pseudoVersionRE` without the `+build` suffix, so there is no new dependency (as the spec requires). A real tag shaped like a pseudo-version reports `0.0.0-dev`, which fails safe.
- Build metadata is rejected: `v0.1.0+dirty` reports `0.0.0-dev`. Since Go 1.24, a clean checkout exactly on a tag stamps `vX.Y.Z` and reports it. The README says so.
- The mapping and its regexes live in `main.go`, because the project structure says cmd holds "main.go only".
- A "Build metadata (#127)" control was added to `.claude/rules/security.md`, and one sentence to the README Security model "Auditable" row.
