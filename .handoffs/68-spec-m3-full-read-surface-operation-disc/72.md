## What was built
At startup the server now detects the deployment profile with `(*langfuse.Client).DetectProfile(ctx, budget)`. It sends an unauthenticated `GET /api/public/health` for the version and one sentinel per family (legacy, v4 read, experiments). The four requests run in parallel within the client's rate limit and concurrency cap, and all of them end within `langfuse.DefaultDetectionBudget` (5 s). Startup resolves the union catalog with that profile and passes the resolved catalog and the profile to `server.New`. It logs `deployment profile` (version or `unknown`, the families on, the operation count), plus one `WARN deployment profile probe undecided` line per probe that could not decide. The warning text is fixed and never holds a Langfuse body. `search_operations` lists only the resolved operations and ranks the v4 family first. `operation_unavailable` hints now name the called operation's own family from the catalog, as well as the version and the families on and off.

## Decisions & deviations
- **Single attempt per probe, no retries.** Retries would eat the budget, and an undecided probe keeps its family on anyway.
- **Any 2xx turns a family on**, including a non-JSON body or one over the size cap. A 400 turns it on too. A 404 with `Unavailable` set turns it off. Everything else (401, 403, a plain 404, 5xx, network, TLS, budget) keeps it on and logs a warning.
- **Only a plain `major.minor.patch` version is kept.** Anything else leaves the version unknown and draws a warning, which keeps every range (story 25). A version below 3.0.0 is kept, with a warning that it is unsupported (ADR-0012 §4, story 27).
- **Ranking** is a sort rule in `catalog.Search`, not an extra parameter. A group whose listed operations include a v4 one comes first, and a group of legacy-only operations comes last. Ties go by tag, then by family rank and ID within a group. The rule applies always: when a family is off, the resolved catalog has already dropped it. The `outputSchema` description of the group order was updated to match.
- **The #78 "one Family definition" AC was not done.** #71 kept duplicate types, pinned by a name-match test. #78 stays open for that part.
- **Test adjustments caused by startup detection:**
  - The proxy tests now allow several CONNECTs, each to the tunnel host.
  - The ambient-CA test checks only for CA warnings.
  - The real-host tests (`cloud.langfuse.com`) route through a dead proxy (`noLangfuseProxy`), so unit tests never reach the network.
