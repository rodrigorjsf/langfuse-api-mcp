## What was built
- **Payload cleaning.** Before a Langfuse payload reaches the agent, every string is cleaned, keys included. Invisible and bidirectional formatting characters are dropped: the Unicode format category Cf plus the whole tag block U+E0000–E007F. Control characters are dropped too, except tab, line feed and carriage return. Echoed error text was already cleaned by `sanitize.Message`, and it stays that way.
- **List operations** are the GET operations that take a `limit` query parameter. When the call names no `limit`, they get `limit=50`. A `limit` below 1 or above 100 is refused with `invalid_argument` and a hint to page through the results.
- **Oversized reads.** A 2xx body above 5 MiB, or a Langfuse 413, returns `response_too_large` with a hint to narrow the query.
- **Oversized results.** A result whose JSON exceeds 100 KiB is truncated and marked with `truncated: true` and a `hint`. A Langfuse page (an object whose `data` is a list) keeps `meta`, which holds the cursor or page, and as many leading rows as fit; the hint names how many rows are shown out of the total. Any other payload becomes a string holding its start, followed by `… [truncated]`.
- **Redaction.** The public key, the secret key, the Basic auth value built from them, the full `Authorization` header and any `pk-lf-…`/`sk-lf-…` key are replaced by `[REDACTED]`. This covers tool results, tool errors and log lines.
- **Audit line.** Each tool call writes exactly one JSON line to stderr, with `tool`, `operationId`, `method`, `status`, `latencyMs`, `bytes` and `code`, plus `cause` for a failed request and panic/stack for a panic. It never contains a payload.

## Decisions & deviations
- **Tab, line feed and carriage return are kept in payload strings.** The acceptance criterion says to strip control characters, but these three are visible text and hide nothing. Every other C0/C1 control character and DEL is dropped. Error text still turns control characters into spaces, as before.
- **The payload is re-encoded.** It is decoded with `UseNumber` and encoded again with `SetEscapeHTML(false)`. As a result, object keys come out in sorted order and the JSON is compact. When two keys clean to the same key, the one that was already clean wins; otherwise the first in byte order wins, so the result is deterministic.
- **Limit: default 50, cap 100, out-of-range values rejected (not clamped).** 100 is the lowest page-size cap Langfuse enforces on a list operation: scores v2/v3 and the legacy routes answer 400 above it. Rejecting instead of clamping means the agent is never silently given fewer rows than it asked for. `observations_getMany` allows up to 1000 upstream but is capped at 100 here. A list operation is a GET with a `limit` query parameter (24 operations). The error is `catalog.ErrLimitOutOfRange`, which also matches `ErrInvalidParameter`; the server attaches the hint.
- **The result cap is 100 KiB (`sanitize.MaxResultBytes`)** on the JSON text, measured as `json.Marshal` emits it. `structuredContent` carries the same JSON, so the MCP message on the wire is about twice that.
- **`server.New` now takes a `server.Secrets{PublicKey, SecretKey}`** (4th parameter), and the server builds its redactor from it. Both `cmd` and `connectClient` pass it. Its `String`, `GoString` and `LogValue` print it as redacted.
- **Where redaction happens.** Caller input (the operation ID, parameter names and Langfuse's message) is redacted before any truncation, because a secret cut short would no longer match. The payload is redacted string by string before truncation. The `audited` wrapper does a final pass over every result and log line.
- **Parameter values are not redacted.** They are sent as given, and only the integer `limit` is echoed back.
- **One audit line replaces the separate failure and panic log lines.** The panic stack now travels inside the audit line.
- **`bytes`** is the size of the response body returned, and is 0 on errors. For `response_too_large`, `status` is Langfuse's 2xx status.

## Code review
Spec axis:
- **Fixed:** truncation dropped `meta` and the cursor, so a page could not be continued. It now keeps page rows and meta and says how many rows fit. The audit `status` was 0 for `response_too_large`; it is now the real status.
- **Dismissed:** parameter values are not redacted before the cut. The only echoed value is the integer `limit`, since a string fails earlier without being echoed. A secret shorter than 10 bytes could push the result a few bytes over the cap; that is negligible.
- **Accepted:** the any-key regex and the stack in the audit line (security rule: redact `sk-lf-…`/`pk-lf-…`).

Standards axis:
- **Fixed:** the nondeterministic key collision in `clean`, the possible endless loop and overshoot in `Wrap` (text cut now uses a binary search, and a real bug was caught by the new non-list test), a `[:200]` panic in a test helper, `keyPattern` over-redacting words such as `task-lf-`, the hardcoded 5 MiB (now `langfuse.MaxResponseBytes`), the `r` name reused for a request (renamed `request`), and the `Secrets` methods now sit next to the type.
- **Dismissed:**
  - `limitError` vs a `%w: %w` wrap: the double wrap would put "limit out of range:" into the agent-facing message.
  - The key pair travels in two structs: `langfuse` and `server` each need it, and depguard forbids `cmd` passing a sanitize type.
  - Redaction at several sites: a documented defence in depth, because truncation forces redaction before each cut.
  - Multi-assert audit test: the one logical property is "the audit line is right".
  - The fuzz predicate mirrors the code: fuzz invariants must restate the rule.
  - The panic value in the log: it is redacted and needed for diagnosis.
  - `CONTEXT.md` terms: optional per `docs-sync.md`.

## Learnings

- A test asserting "no secret" must check partial runs of the secret: truncation leaks prefixes.

## Notes for dependent tickets
- `server.New(cat, client, log, server.Secrets{PublicKey, SecretKey})`.
- Tool handlers are wrapped by `audited(log, redactor, handler)` (`internal/server/audit.go`). A handler has the signature `func(ctx, req, a *audit)` and sets `a.method`, `a.status`, `a.bytes` and `a.cause`. New tools (`search_operations`, workflow tools) should use the same wrapper.
- `sanitize.Payload(raw, redactor)` cleans a payload, and `sanitize.Wrap(opID, payload)` builds the envelope and applies truncation. `sanitize.NewRedactor(...)` and `Redactor.Redact` handle redaction; `sanitize.Text` strips hidden characters.
- The catalog exposes `catalog.DefaultLimit = 50`, `catalog.MaxLimit = 100` and `catalog.ErrLimitOutOfRange`. The langfuse package exposes `langfuse.MaxResponseBytes` and `langfuse.ErrResponseTooLarge`, returned with `Response.Status` set.
