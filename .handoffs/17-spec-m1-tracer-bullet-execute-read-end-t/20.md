## What was built
- A non-2xx answer from Langfuse now reaches the agent as an ADR-0008 tool error that follows the errors-rule status table: 400 `langfuse_bad_request`, 401 `langfuse_unauthorized`, 403 `langfuse_forbidden`, 404 `langfuse_not_found`, 409 `langfuse_conflict`, 422 `langfuse_unprocessable`, 429 `langfuse_rate_limited`, 5xx `langfuse_unavailable`. A 4xx that is not in the table (e.g. 405) becomes `langfuse_bad_request`.
- `message` is "Langfuse answered HTTP <n>: <Langfuse's explanation>". The explanation is built from a JSON body: message, zod issues as `path: message`, the error string, `errors[]`, SCIM `detail`. It is sanitized (control, zero-width, bidi and tag characters removed) and cut to 500 runes with the marker `… [truncated]`. Bodies that are not JSON are never echoed.
- A 404 with an HTML body, or whose body names `events_only` or "v4 write mode", becomes `operation_unavailable`. The hint names the family and a replacement operation. The body is never echoed.
- GET retries happen inside a 60 s deadline per call: 5xx is retried at most twice, with backoff 250 ms then 500 ms and equal jitter (each wait in [d/2, d]). 429 is retried once, only when `Retry-After` is present and fits the deadline. `retryAfterSeconds` is rounded up.
- A panic in the tool handler becomes `internal_error`. The stack trace goes to the stderr logger only, and the session keeps serving calls.

## Decisions & deviations
- **The per-call deadline is a context deadline.** `Options.RequestTimeout` (default `DefaultRequestTimeout` = 60 s) replaces `http.Client.Timeout`, so a single deadline covers every retry and its waits. #21 should classify `context.DeadlineExceeded` from `Do` as `timeout`.
- **Time is injected through `Options.Wait`.** The default is a real timer that honors ctx. Jitter uses `math/rand/v2` (nolint G404, not a secret). `fits()` compares against the real clock.
- **A 429 without `Retry-After` is not retried** ("never blind-retry"). It still returns retryable with `retryAfterSeconds: 0`, and the hint explains what 0 means.
- **Unlisted 4xx map to `langfuse_bad_request`**, because the table has no row for them. Until #22 lands, **413 also maps to `langfuse_bad_request`**. #22 must add a 413 → `response_too_large` case in `statusErrorFor`.
- **Every status appends Langfuse's JSON message**, not only 400: 403 "Organization-scoped API key required" is actionable. The message is sanitized and bounded.
- **New `sanitize.Message(s)`** strips control and Cf characters, replaces invalid UTF-8 and truncates to `sanitize.MaxMessageRunes`. `errorResult` applies it to every tool error message (invalid_argument included). #22 may reuse it for payloads or merge its own stripping into it.
- **`langfuse.APIError`** has `{Status, Code, Message, Unavailable, RetryAfter}`. `errors.Is(err, langfuse.ErrOperationUnavailable)` holds when `Unavailable != ""`. `Error()` never includes the body.
- **Fixture completeness.** The captured prototype bodies were truncated ("...") in RESULTS.md and scan.json. The fixtures use the captured prefixes: `events_only` message verbatim up to "mode.", and the HTML page prefix closed with a minimal body. The "v4 write mode" body is complete.
- **No detected version in the `operation_unavailable` hint.** There is no deployment profile in M1. Filed as #34.

## Learnings
- Python heredoc edits that write `‮` into Go source put literal bidi characters in the file, and staticcheck ST1018 flags them. Keep the escapes, not the raw characters.
