# Handoff — #91: A connection reset under load can surface as internal_error instead of a retryable network_error

## What was built
A Langfuse host or proxy that drops the connection before answering is now always a `network_error` (retryable). A read is retried twice under the existing retry budget. Before, a reset that landed after the request write reached `http.Client.Do` as `*url.Error{Err: io.EOF}`. That error fell through `classify` to `internal_error` with a "report a bug" hint. A body cut short after the answer started keeps its class: `internal_error`, not retried, with nothing echoed.

## Decisions & deviations
- The rule applies only in the request phase: new `classifySend` is used only for the `http.Client.Do` error. Body reads keep `classify`.
- Only `io.EOF` is mapped, because that is the observed error. `io.ErrUnexpectedEOF` (for example a status line cut short) was not observed, so it is not mapped.
- Deterministic reproduction: a host that reads the request and closes cleanly (FIN) yields the same `*url.Error{Err: io.EOF}` as the load-dependent reset, so the test does not depend on load.
- Docs: the `network_error` row in `README.md` and in `.claude/rules/errors.md`, plus the `resettingListener` comment.

## Code review
- Fixed: `classifySend` compared error identity (`classified != err`), so it relied on a hidden contract. It is now refactored to `failureClass` (returns the sentinel or nil) plus `wrapClass`.
- Fixed: the `ErrNetwork` doc now also names "a connection dropped before any answer".
- Fixed: the README row no longer carries the `(#91)` tracker reference.
- Dismissed: duplicated listener helpers across tests. They sit in separate test packages, and the reset and clean-close shapes differ.
- Dismissed: the hand-kept sentinel list in the truncated-body test. It follows the existing test style, and the server test also asserts internal_error.
- Dismissed: `noWait` next to `fakeClock.Wait`. It is a one-line stub, and a clock is not needed.
- Dismissed: no DELETE through the EOF path. The no-retry-for-writes rule depends on the method only (`retries.next`), and `TestAWriteThatFailsOnTheNetworkIsNeverRetried` proves it.
- Dismissed: no unknown non-EOF error through `classifySend`. No such error can be produced at the seam, and the default branch is shared with `classify`.
- Spec axis: all criteria met, no scope creep.
