## What was built
- When a request never gets a Langfuse answer, `execute_read` now returns a structured ADR-0008 tool error instead of the old `internal_error` catch-all.
- A server certificate from an untrusted CA returns `tls_untrusted_certificate`. The hint names `LANGFUSE_CA_CERT`, `LANGFUSE_CA_CERTS_PATH` and the "CA sources loaded" startup log line.
- Any other certificate verification failure (host name, validity, usage) also returns `tls_untrusted_certificate`, with a different message. Its hint adds a check that `LANGFUSE_BASE_URL` names the certificate's host.
- DNS failure, connection refused and connection reset return `network_error` (`retryable: true`). The hint names the `LANGFUSE_BASE_URL` host and `HTTPS_PROXY`/`NO_PROXY`. A GET is first retried twice (50 ms base, exponential backoff with jitter, within the deadline). Non-GET methods are never retried.
- When the request deadline passes, the call returns `timeout`. When the MCP client cancels, it returns `canceled`. Both carry a hint to narrow the query.

## Decisions & deviations
- **Where the code lives.** Classification is in `internal/langfuse/failure.go` (the exported sentinels `ErrUntrustedCertificate`, `ErrCertificateRejected`, `ErrNetwork`, `ErrTimeout`, `ErrCanceled`, and an unexported `classify`). Translation is in `internal/server/failure.go` (`executor.failure` and `failureFields`). `failure` is now the single place that replaces the old `internal_error` catch-all in `executeRead`, and #20 should add the `APIError` cases to `failureFields`.
- **Retry loop.** The retry is in `internal/langfuse/send.go` (`Client.send`). `Do` calls `send` instead of `httpClient.Do`.
- **Deadline.** Added `langfuse.Options.Timeout` (default 60 s). `Do` applies it as a context deadline that covers retries and the body read. `http.Client.Timeout` was removed so that a timeout can be told apart from a cancellation. `cmd` does not set `Timeout` (it uses the default). Making it configurable is M2 scope.
- **Certificate failures share one code.** Both certificate failure kinds map to `tls_untrusted_certificate` (the ticket names both), and I updated the `.claude/rules/errors.md` row to match.
- **Cancellation is checked through the log.** A canceled MCP client never reads the tool result, so the S1 test asserts the `"code":"canceled"` field of the server's stderr failure line. The `canceled` hint is not observable at S1. The failure log line now carries `code`.
- **DNS test.** The DNS test uses `langfuse.invalid`. RFC 6761 reserves `.invalid`, so resolvers answer NXDOMAIN and no Langfuse is contacted.
- **Classification order.** A DNS lookup that times out is `network_error`, and it is checked before the generic net timeout.

## Code review
Standards:
- Fixed: the `errors.md` TLS row now covers verification failures.
- Dismissed: the DNS test counts as network use. The resolver-only NXDOMAIN for `.invalid` is reserved by RFC 6761, and the test passed on Linux and on the Windows binary.
- Dismissed: the logged `url.Error` includes the query. This predates the change, and #22 owns the logging and audit line.
- Dismissed: the name `failure` and the hardcoded "execute_read failed" message. It is the only tool so far.
- Dismissed: the reset-listener test code appears twice, but in different test packages.
- Dismissed: remote TLS alerts (`*net.OpError`) are classified as a retried `network_error`. This is a minor edge case (mTLS). The retry is harmless for a GET, and `network_error` is the best available code.
- Dismissed: "one assertion per test". Each test asserts one tool-error shape.

Spec:
- Fixed: a DNS timeout was classified as `timeout`. It is now `network_error`.
- Fixed: the `errors.md` row.
- Filed as a follow-up: proxy failures (#32).
- Noted: the cancel hint cannot be observed at S1. A network error during the body read is `retryable` but is not retried by the server, which is consistent with the rule.

## Learnings
- go-sdk v1.8.0: a canceled `CallTool` never delivers the tool result. Assert cancellation through the server's log.
- `noctx` lint flags `net.Listen` in tests. Use `new(net.ListenConfig).Listen(t.Context(), …)`.
- `SetLinger(0)` followed by `Close` on an accepted conn gives a reliable `*net.OpError` reset, so tests can count network retries.
