## What was built
A result over the result size cap now keeps every row and every observation. `sanitize.Wrap` first clips the largest string values (each keeps its first bytes and ends in the static marker `… [clipped]`), by the least that fits: one ceiling for all values, found by bisection, so only the largest are touched and a result that fits is returned untouched. Only when clipping every value to the 128-byte floor is not enough are rows left out, at a row boundary, from the payload's list of rows: a page's `data`, or the largest list of an object (the observations of a v3 `trace_get`), so an object stays an object. A payload with no list of rows falls back to the old text cut. `truncated` is set and `data` stays valid JSON. Hints are static and built from the parameters the operation serves on the deployment (`fields`, `limit` up to 100, a time filter, paging), and say when one value is larger than any result can hold. A continuation cursor is never clipped.

## Decisions & deviations
- One ceiling for all values (found by bisection on the exact encoded size, HTML escaping included) is the continuous form of "largest first"; the floor is 128 bytes (`clipFloor`), a value is only clipped if that makes it shorter, at a character boundary.
- Row list: page `data`, else the payload if it is a list, else the largest list reachable through objects. Added after the Spec review found that a v3 `trace_get` (object with `observations`) fell to the old unparseable text once clipping to the floor was not enough (H3 again).
- A continuation cursor (`cursor` key) is never clipped (review finding: a clipped cursor breaks paging; security.md #93).
- `fields` is named for an operation that serves it, but its values are not: the catalog holds no enum for `fields`, and describing the values per operation is story 23 (guidance ticket) of this spec. Naming them here would hard-code unverified text.
- The row hint suggests `limit` no higher than `catalog.MaxLimit` (100); the old hint could suggest a limit the server refuses.
- `Remedies` (sanitize) carries the operation's ways to ask for less; the facts come from new `catalog.Operation.HasQueryParam` / `HasTimeFilter`, the placement table's home for parameter knowledge. `WrapWith` (trace tree) takes a fixed remedy sentence instead.
- Not re-fitted: after rows are left out, kept values stay at the floor; the room left is less than one row at the floor, so re-fitting gains little.
- Payload with no list of rows that still does not fit after clipping to the floor: text cut with `… [truncated]` as before (documented in tools.md).
- Existing tests updated because behaviour changed by design: list/trace-tree tests that expected rows dropped now expect all rows with clipped values; the object-as-text test needs a payload with no list.
- ADR-0002: refined line about the 100 KiB row truncation and added one sentence to the M8 amendment (no new ADR: a refinement, not a contradiction).

## Learnings
- `go test -race ./...` run once showed a flake in `cmd/langfuse-mcp` (see #191); rerun the package alone before suspecting your change.
- A fake Langfuse behind `langfuse.New(testOptions(...))` is rate limited to 30 requests a minute; a test that loops many calls sets `opts.RateLimit`.
- `gofmt`/`go fmt` rewrites `‮` escapes only if they were typed as literal characters; editors/tools that expand `\uXXXX` in a pasted Go string put hidden characters in the source and gosec G116 flags it.
- `git checkout <file>` to undo a mutation test also discards uncommitted real edits to that file; copy the file aside first.
