## Decisions & deviations
- **Description cut to 200 characters or fewer (absorbed).** The support.claude.com article "How to create custom Skills" caps the description at 200 characters and wants the skill folder as the ZIP root. The old description had 318 characters, so the ZIP could have failed upload, and the AC requires the "layout Claude Desktop's upload expects". The new description still names the five tools and the tasks, including sessions. The eval A/B for intents 03 and 05 was not re-run with the new description. ROADMAP flags this against exit criterion 1.
- **`SKILL.md` kept upper-case.** The help-page summary said `skill.md`, but `npx skills add` needs `SKILL.md`, and so do Anthropic's own skills.
- **ZIP name** `langfuse-api-mcp-skill_<version>.zip`. It is written under `dist/skill/`, so the `dist/*.zip` release-archive glob does not pick it up.
- **Signed.** The ZIP joins the signed and attested artifacts, beside the `.mcpb`. It is not in `checksums.txt`, which GoReleaser writes earlier.
- **`skills/**` not added to the `release.yml` PR paths.** Adding it would run the full release matrix on every skill Markdown edit. CI's `check-skill.py` guards the content, and a push to `main` rebuilds the ZIP. This is documented in the README.
- **The pack walks the disk.** The workflow check against `git ls-files` rejects untracked junk in CI. This is documented in the script header.
- **The ZIP check follows git, not a count of files,** so `errors.md` (#138) is covered when it merges.
