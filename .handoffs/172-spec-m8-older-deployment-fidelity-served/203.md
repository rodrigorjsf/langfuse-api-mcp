Status: DONE

## What was built
The hint of `response_too_large` (a Langfuse 413 or a body over the bytes this server reads) and the hint of a `timeout` or `canceled` call now name only the ways of narrowing the called operation has: fewer field groups (#194), a lower `limit` (only an operation with a `limit` parameter), a shorter time window (only one with a `date-time` query parameter), from one compiled source shared with the truncation hint. An operation with none (`trace_get` on 3.80.0) gets fixed text: "no parameter of this operation makes the answer smaller / the call cheaper: tell the user instead of calling again". It never says "narrow the query" and never invites another call. `get_trace_tree` gets fixed text per source for a timeout or canceled call (it sends the agent to `execute_read` with the operation it reads). A failed filter scan names neither a lower `limit` nor paging. A failed write keeps its not-retried note and names a way after it only if the write operation takes one (none does today). The hint of a call held by the server's own limits is unchanged.

## Decisions & deviations
- **Metrics operations (deviation, judgement call).** `metrics_metrics` and `legacy_metricsV1_metrics` take no `limit` and no `date-time` parameter, so the ticket's rule as written would tell them "no parameter of this operation makes the answer smaller", which is false (their `query` JSON holds the time range, filters and `config.row_limit`). I added a fourth way to the shared source, `Remedies.MetricsQuery` / `catalog.Operation.HasMetricsQuery`: "a shorter time range, more filters or a lower config.row_limit in the query JSON". The truncation hint of those two operations gains the same words (it had no remedy before); the walk and the three hints stay in agreement. Documented in `tools.md`.
- **One word order.** The three hints now share the truncation hint's order (fields, limit, window); the too-large and timeout hints changed order for operations with several ways, and the literals of #194's tests were updated.
- **A 413 on a trace tree page** gets the same too-large hint the over-the-cap case already had (its text is unchanged, #193); before it got the generic hint that named a limit and a window the tool lacks. Absorbed, small, tested (`TestTheHintOfATraceTreePageAnswered413IsTheTooLargeHintOfTheSourceItReads`).
- **A write answered 413 or over the cap** now reads "no parameter of this operation makes the answer smaller: tell the user instead of calling again" (writes have no way of narrowing); tested.
- **Zero-way texts** (words are mine, within the ticket): too large "no parameter of this operation makes the answer smaller: tell the user instead of calling again"; timeout "no parameter of this operation makes the call cheaper: tell the user instead of calling again"; canceled adds the lead-in "if the call was canceled because it was slow, ". An operation with paging but no narrowing way (none exists) would get the fixed text too.
- **`get_trace_tree` timeout texts**: "get_trace_tree has no argument that reads less: execute_read with observations_getMany (traceId, fields, a lower limit, cursor) reads the trace in smaller pages" and the legacy form; the too-large constants are now built from the same two "reads the trace in smaller pages" constants and read byte for byte as before.
- **Filter scan**: `scanReads(op)` drops `limit`, `page` and `cursor` from the operation the scan reads; the failure hints and the (existing) truncation hint both use it.
- **Writes**: `notRetriedHint(f, op)` takes the operation; a timed out or canceled write gets the not-retried note plus the ways of narrowing only when the write operation has any (no catalog operation does; proven on a literal operation).
- **Time filter definition kept as the ticket says** (a `date-time` query parameter), so `legacy_observationsV1_get` (single-resource read with a `startTime` lookup hint) is told "a shorter time window". That is wrong advice for one observation; changing it changes the #177 truncation hint too, so it is filed as #204.
- `JoinWays` and `FieldsWay` of `sanitize` became unexported (no caller outside the package left); their old test is covered by `NarrowWays`.

## Learnings
- The Go toolchain is not on PATH: `export GOROOT=$HOME/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-amd64; export PATH=$GOROOT/bin:$HOME/go/bin:$PATH`.
- A fake Langfuse that stalls a POST must read the request body first, or the server notices the closed connection only when the handler's 10 s timer ends.
- The default client rate limit is 30 a minute: a test that makes more than a handful of calls through one client waits seconds; set `opts.RateLimit` high.
- A unicode escape typed in a file written by the Write tool or a heredoc can land as the real hidden character; write it with `chr(92)` from Python and `grep -P '[\x{200b}\x{202e}\x{1b}]'` the files afterwards (the #178 and #194 learning, met again).
- `TestRedactionTimeGrowsInProportionToTheInput` (sanitize) failed once when run in parallel with the other packages (a timing ratio) and passed alone and on the next runs: a load-sensitive test, not a #203 effect.
- `scripts/race-memory.sh ./internal/server` now runs the whole `server` race suite in one process (peak about 1.9 GiB), no pieces needed since #201.
