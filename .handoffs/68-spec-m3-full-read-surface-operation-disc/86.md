## What was built
The fake CONNECT proxy in `internal/server/proxy_test.go` now records method, target host and `Proxy-Authorization` for every request it receives. Every proxy failure message lists all recorded requests. The tests count only CONNECTs to the tunnel target (`langfuse.test:443`). The credentials test requires that every such CONNECT carries the Basic credentials; one matching entry is not enough. A new test drives a retried read through a credentialed proxy. Every answer closes its connection, so each attempt opens a new tunnel. The test proves that all 3 CONNECTs carry the credentials. No production code changed: the evidence shows the transport is not at fault.

## Decisions & deviations
- The host/method filter cannot exclude the #86 stray itself: that stray was a `CONNECT langfuse.test:443`, the same method and target as a real call, because the proxy-refusal test also targets `https://langfuse.test`. The filter drops only strays with another method or target. The flake is fixed at its source by #77's port-holding `refusedURL`. A same-target stray would still fail the per-request assertion, as the spec requires ("some entry matches" is not enough). The `tunnelConnects` comment says so.
- The retried-CONNECT test was added even though the transport was not at fault. The spec asks for it only "if the transport was at fault". I kept it because the brief requires the credential hypothesis to be "ruled out with evidence, not assumed away", and this test is that evidence.
- 150 runs of the proxy subset with the pre-#77 helper did not collide on their own (the collision is rare), so the cause is shown by the deterministic experiment above rather than a natural reproduction.
- Refactor: `tunnelLangfuse` now delegates to `tunnelLangfuseWith(t, ca, handler)`.
