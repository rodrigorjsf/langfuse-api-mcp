## What was built
When the operator sets no `LANGFUSE_MCP_RATE_LIMIT`, `config.Load` picks the default from the host of
`LANGFUSE_BASE_URL`: exactly one of the four Cloud hosts gives 30/min (`default-cloud`), and any other host,
loopback included, gives 1000/min (`default-self-hosted`). An explicit value from the environment or the
config file always wins (`explicit`), and its validation is unchanged. The startup log carries one line,
`{"msg":"rate limit","perMinute":N,"source":"..."}`. The README "Request limits" section documents both
defaults, the explicit-wins rule and the paid-plan caveat, and the "default under review" link is gone.
`LANGFUSE_MCP_MAX_CONCURRENCY` is unchanged.

## Acceptance criteria
- [x] Each Cloud host with no explicit value gives 30. A self-hosted host and loopback hosts give 1000. Tests: `TestLoadDefaultsTheRateLimitTo30OnEveryCloudHost` and `TestLoadDefaultsTheRateLimitTo1000OnASelfHostedOrLoopbackHost` (internal/config/limits_test.go).
- [x] An explicit value wins on a Cloud host and on a self-hosted host, from the environment and from the config file. Test: `TestLoadLetsAnExplicitRateLimitWinOnAnyHost`.
- [x] Host matching is exact, case-insensitive and ignores the port. Look-alike hosts are not treated as Cloud: suffix, substring, subdomain, userinfo, path, query, fragment, trailing dot, and U+017F `ſ`. Test: `TestLoadDoesNotTreatALookAlikeHostAsACloudHost`.
- [x] The startup log line carries the effective limit and its source; all three sources are asserted. Test: `TestStartupLogStatesTheEffectiveRateLimitAndItsSource` (cmd/langfuse-mcp/main_test.go). The log holds no keys: `TestStartupLogNeverHoldsTheLangfuseKeys`.

## Decisions & deviations
- `Config.RateLimit` is now the effective value and is never 0 after `Load`. The new `Config.RateLimitSource` field has type `config.RateLimitSource`, with the constants `RateLimitExplicit`, `RateLimitDefaultCloud` and `RateLimitDefaultSelfHosted`. The `langfuse.DefaultRateLimit` fallback is unchanged, as the spec requires; only its comment was updated.
- Host matching folds ASCII case only (`asciiLower`), not `strings.EqualFold`. Unicode folding would map `ſ` (U+017F) to `s`, so `cloud.langfuſe.com` would have counted as Cloud. The test saw this fail (red) before the fix.
- The Cloud host list is `var cloudHosts = [...]string{...}` in internal/config/limits.go, because Go has no const arrays.
- The rate-limit log line is emitted after the last startup step that returns an error. An existing test requires exactly one log line on a failed startup.
- The `mustLoad` test helper now drops the host-derived rate-limit default (an explicit value is kept), just as it already dropped `Connection`. This keeps the existing whole-struct CA tests focused. The old test `TestLoadLeavesTheLimitsUnsetSoTheClientDefaultsApply` became `...MaxConcurrencyUnset...`, and the fuzz expectation for "" is now 30, on an explicit Cloud host.
- The explicit-wins branch went in during the first slice to restore the existing explicit-value tests, so the explicit-wins tests passed on first run. The spoofing tests passed on first run except the `ſ` case.
- Docs: README "Request limits" was updated. CONTEXT.md "Request limits" now says the unset rate limit's default depends on the Cloud host. ROADMAP was not touched, because M2 is marked done only when all tickets of #58 merge.
