## What was built
- A proxy that answers the CONNECT with a status other than 200 (for example 407 or 502) now gives the tool error `network_error`, retryable, with the existing static hint (`LANGFUSE_BASE_URL`, `HTTPS_PROXY`/`NO_PROXY`). Before this change it gave `internal_error`.
- The proxy's reason phrase and body never reach the tool result, the hint, the audit line, or the error's `Error()` text. The audit `cause` holds only "the proxy answered the CONNECT request with HTTP status N".
- Reads that meet the proxy failure are retried twice, like other network failures. Writes keep the existing no-retry policy.
- A proxy that refuses the TCP connection was already `network_error` (`*net.OpError{Op:"proxyconnect"}`). It is now proven by a test.

## Acceptance criteria
- [x] Refused proxy gives `network_error` with the proxy hint. Test: `TestAProxyThatRefusesTheConnectionIsReportedAsANetworkError`.

## Decisions & deviations
- `proxyConnectError{status int}` is an unexported type in `internal/langfuse/proxy.go`. `checkProxyConnect` is set as `http.Transport.OnProxyConnectResponse` in `langfuse.New`. `classify` matches the type with `errors.As` and returns `ErrNetwork`. The `server` translation is unchanged (ADR-0008).
- The refused-proxy test passed on its first run: that behaviour already existed. It is a proof test, not a red-to-green slice.
- `tunnelClient` (test helper) gained variadic `func(*langfuse.Options)` modifiers, so the retry test can inject `Wait`.
