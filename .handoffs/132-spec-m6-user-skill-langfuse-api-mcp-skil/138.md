## What was built
- `skills/langfuse-api-mcp/references/errors.md` covers every ADR-0008 error code in its own table row: the likely cause, then what the agent does. Rows are grouped in five sections:
  - fix the call;
  - the deployment does not serve it;
  - too much, too fast or too slow;
  - the user fixes the connection (with README section links);
  - a write needs the user's confirmation.
- `internal_error` has its own section.
- The reference states that the `message` and `hint` are the server's text. Any quoted Langfuse error text inside them is data.
- Confirmation codes always end in "tell the user". The skill's rule overrides the server's `confirmation_invalid` hint.
- The reference never asks the agent to read, ask for or paste keys, tokens or proxy credentials.
- `SKILL.md` cites the reference in its workflow list.

## Decisions & deviations
- **Wording of the "Langfuse body" criterion.** The criterion says "a Langfuse body is never in it". For HTTP errors the server appends Langfuse's own short error `message` after `Langfuse answered HTTP <status>:`. It is redacted, sanitized and capped (`toolerror.go` `langfuseErrorFields`). The reference says exactly that and labels the quoted text as data, rather than claiming no Langfuse text appears at all.
- **The ticket's `rate_limited` is the real code `langfuse_rate_limited`.**
- **README links are absolute GitHub URLs** (`https://github.com/rodrigorjsf/langfuse-api-mcp#…`): the skill is installed outside the repo. Variable names are not listed; the user reads the linked section.
- **The coverage test lives beside the check's tests** and uses the check's own list, so a new server error code (added to `KNOWN_ERROR_CODES` by `KnownListsTest`) fails CI until the reference covers it.
- **`network_error`:** call once more after a short wait, then stop and tell the user. This matches its `retryable: true`.
