## What was built
`sanitize.Redactor.Redact` now also replaces the token of `Authorization: <scheme> <token>` and of `Bearer <token>` with `[REDACTED]` and keeps the scheme word (`Authorization: Bearer [REDACTED]`). A token is at least 16 printable ASCII characters other than space, `"`, `'`, backtick and backslash; prose that only names the words is left alone. Because `Redact` is the one redactor every channel uses, the rule reaches tool results (text and structuredContent, payload strings and keys, before clipping), Langfuse error text (before the 500-rune cut), the operation ID, parameter name and argument name an error echoes (before the 64-byte cut), the audit line, a last pass over each result's JSON text, and the confirmation text (body summary redacted before its 300-rune cut). An invisible or control character inside a credential no longer hides it: the text is matched without them, and they are dropped from a text that held a secret (this also fixes the same hole for Langfuse keys).

## Decisions & deviations
- Minimum token length 16 (96 bits of base64; above the 10 characters of `[REDACTED]`, so redacting twice changes nothing — `TestRedactingARedactedTextChangesNothing`, `FuzzRedact`).
- Token characters: printable ASCII minus space, `"`, `'`, backtick, backslash. The quote and backslash exclusion keeps the last pass over a result's JSON text valid JSON (`FuzzRedact`); non-ASCII is excluded (RFC 6750 credentials are ASCII). A credential holding such a character is redacted only up to it, if that part has 16 characters (documented, pinned by `TestRedactEndsATokenAtABackslashAQuoteOrANonASCIICharacter`).
- Keywords match in any case at a `\b` (so a hyphen starts a word: `Proxy-Authorization: Basic …` is redacted), blanks around the colon, `[ \t]` only (a token on the next line is not taken). The keyword part uses `(?i:…)` only, because `(?i)` on the token class would admit the Kelvin sign and long s.
- The shape is all that is checked (as the ticket says): a long word or URL right after `Bearer`, or after `Authorization: <word>`, is taken for a token. Documented with examples and pinned (`TestRedactTakesALongWordOrURLAfterTheKeywordsForAToken`). A digit requirement was rejected: it would let an alphabetic 24-character token through and goes beyond the ticket.
- `Redact` strips hidden characters (via `Text`) before matching, but returns the text untouched when no secret is found, so callers that look an ID up by the returned text (operation IDs, parameter names) never see a hidden-character ID turn into another one. When a secret is found the hidden characters are dropped from the whole text (Spec reviewer: a behaviour change beyond header tokens; it follows from the invisible-split criterion and also closes the hole for Langfuse keys).
- Performance (go.md asks for numbers): `mentionsHeader` prefilter and a byte-scan `plain` fast path in `Text`. `BenchmarkRedact`, 64 KiB of ASCII JSON: 3.7 ms before the two fast paths, 0.134 ms after (non-ASCII text 0.93 ms, the cost of cleaning it by rune). `Payload` calls the unexported `redact` on text it already cleaned, so strings are not cleaned twice.
- The confirmation text: its body summary is now redacted before the 300-rune cut (`bodySummary` takes the redactor). Initially filed as follow-up #197, absorbed after the Spec review ("redaction runs before any length cut"). #197 is open with a comment; close it when the PR merges.
- Not done on purpose, filed as #196: the value of a JSON header map under an `Authorization` key is redacted only when it starts with `Bearer` (key and value are separate strings; a key-aware rule needs its own design). Named in the three docs.
- Docs row added to the risk-to-control mapping (`docs/research/security.md`), `tools.md` Secrets row, `ROADMAP.md` M8 line.

## Learnings
- A backslash-u escape typed into Write/Edit becomes the real character (the first draft of this very line did); build hidden characters from code points (`string(rune(0x200b))`), as #179 noted.
- `strings.Repeat("b", 30000)` right after a planted `Bearer <token>` made the token swallow the filler (a token is a run with no whitespace); put a space after the planted credential in tests, or a test can pass for the wrong reason (it did, until a size guard exposed it).
- A cut-point test is vacuous unless it is red against the old code: probe a range wide enough that the cut falls inside the token by at least the leak run (found by running the new tests against `git show <base>:file`).
- gosec G101 flags names containing `token`/`cred`/`secret` and high-entropy literals in non-test code too: name the regexp class `valueChar`, nolint a fake token in a test.
- Go `(?i)` on a character class folds in look-alike non-ASCII letters (Kelvin sign): scope it with `(?i:…)` to the keywords.
- Output files of background agents under `tasks/*.output` are symlinks: `stat -L` for real sizes and mtimes.
