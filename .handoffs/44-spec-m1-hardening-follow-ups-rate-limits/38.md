## Decisions & deviations
- Option 2 of the issue: `KeyPair` lives in `internal/langfuse`.
- `KeyPair.RedactionValues()` is exported, so the server's redactor can read the raw values. This is the second consumer the issue's Gotcha asks for. It differs from the brief's literal wording, "only the client's auth header builder reads the raw values". The Basic-value derivation stays inside `langfuse`. The doc comment says the method is for building a redactor only.
- The keys are held behind a pointer. This hardening goes beyond the brief, and it answers the issue's point that "a new struct that copies them would not redact".
- `server.Secrets` was kept, with one field, because spec #44 names it as an interface ("replaces the two key strings in `langfuse.Options` and `server.Secrets`").
- The Options/Client String trios in `langfuse` were kept. They also redact the Host through `url.Redacted`.
