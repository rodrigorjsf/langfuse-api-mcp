## What was built
- A paging hint names only the way of paging the called operation has, from its served parameters: `page`, `cursor from meta.cursor`, both, or neither. The hint of a `limit` out of range, the hint of a parameter the deployment's version does not serve, the hint of a `response_too_large` and the truncation hint of a page that lost rows follow the rule. On a v3 deployment no hint sends the agent to a cursor.
- `get_trace_tree` on Observations v2 gets its own too-large hint (execute_read with `observations_getMany`, its parameters named), like the legacy path already had.
- A terminal escape sequence in Langfuse data goes whole: a CSI (ESC `[` or U+009B, parameter and intermediate bytes, one final byte) and an OSC (ESC `]` up to BEL or ESC `\`, an OSC 8 hyperlink with its URL). The scan reads at most 256 characters (`sanitize.MaxEscapeSequenceRunes`); an escape character that starts no complete sequence goes alone and the text after it stays. Text such as `[31m` with no escape character before it is never changed. It runs in `sanitize.Text` (payload strings and keys, `Line`, `Redact`, the audit line, confirmations) and `sanitize.Message` (Langfuse error text), before redaction and before the result size cap is measured.

## Decisions & deviations
- Scan bound: `MaxEscapeSequenceRunes = 256` characters from the escape character, terminator included; exported so the tests and docs name it. Over it, or a control character other than the terminator in an OSC, or a non-ASCII character in a CSI: the escape character goes alone (as every control character does today), the rest stays.
- Only CSI and OSC are removed whole, as the ticket lists them. Other escape forms (`ESC ( B`, DCS, `ESC c`) keep today's behaviour: the escape character alone. The one-character OSC (U+009D) is not covered either (ticket names only U+009B).
- JSON safety (deviation from plain ECMA-48): the one-character CSI (U+009B) ends its scan at `"` and `\`. U+009B can stand raw in a JSON text, and `Redact` runs on the JSON text of a result (`FuzzRedact` asserts valid JSON stays valid); without this a raw U+009B before `"}` would take the quote and break the JSON. The `ESC [` form takes quotes and backslashes as intermediate and final bytes (a Spec-review finding narrowed the exception to U+009B; ESC cannot be raw in JSON).
- `catalog.visible`/`visibleText` (embedded OpenAPI spec text, stripped at load) do not remove sequences whole: not Langfuse data read at run time; the catalog may not import sanitize. Noted in the function comment.
- "Both ways of paging" at the server seam: no catalog operation has `page` and `cursor`, and none has `limit` with neither, and the catalog has no constructor for a hand-built operation. Those cases are proven on literal `catalog.Operation` values through test-only exports (`export_test.go`: `LimitHint`, `NotServedHint`, `TooLargeHint`), plus the pure `TestPagingWaysNameOnlyTheParametersTheOperationHas`. The real-operation cases (page only, cursor only, neither) go through the MCP client. A page-only not-served hint on a v4 profile does not exist in the catalog (every `page` parameter is served from 3.x).
- Truncation hint: `Remedies.Paging bool` became `Page, Cursor bool` with `PagingWays()` and `PagingNote()`; the hint now reads `page through the rest (page)` / `(cursor from meta.cursor)` / `(page, or cursor from meta.cursor)`. The doc example in `tools.md` shows it.
- `failureFields(op, err)` and `statusErrorFor(status, op)` take the operation so `response_too_large` can name its paging.
- Only the paging words of the `response_too_large` hint were changed: its `fields`, time window and limit words stay (#194 owns `fields`, #203 the other two).
- The `get_trace_tree` Observations v2 too-large hint names `fields` (the tool's operation serves it); #194 should keep it consistent with its rule.
- Not changed: the user skill's `references/errors.md` line "Then page through the rest" (client-side generic guidance; spec: the skill is not changed for v3).

## Learnings
- Write and edit tools expand `\uXXXX` typed inside a Go string into the raw character (here U+200B): staticcheck ST1018 flags it; scan the file for Cf/Cc characters after writing tests.
- `go` is not on the bash PATH: `export PATH=/home/rodrigo/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.1.linux-amd64/bin:$PATH GOTOOLCHAIN=local`.
- `ulimit -v` breaks the race detector (ThreadSanitizer cannot map its shadow memory); chunk the server tests from one compiled race binary instead (`-test.list`, then `-test.run '^(A|B|…)$'`).
- `Redactor.Redact` returns the original text when it finds no secret: a test of what it cleans needs a planted secret, or `Text`.
