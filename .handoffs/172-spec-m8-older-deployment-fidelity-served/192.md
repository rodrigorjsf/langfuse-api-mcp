## What was built
- With write mode off, `execute_read` called with a write operation ID answers `operation_not_found` in the words and with the hint of an ID in no release (`unknown operation ID "x"`), naming no HTTP method and sending nothing; `describe_operation` already did. With write mode on, `execute_read` keeps `invalid_argument` naming the method and pointing to `execute_write`.
- In write mode every write line of the operation index says its HTTP method and whether it is destructive: text `(execute_write, DELETE, destructive)` / `(execute_write, POST, not destructive)`, structured entries gain `method` and `destructive` (the value `describe_operation` returns); the output schema declares both. Read lines and the read-only index are unchanged.
- `describe_operation` (write mode) returns a static `body.guidance` for `comments_create` (`projectId` is the ID of the project the server's keys belong to; `projects_get` returns it) and `scores_create` (a score needs exactly one target: `traceId` with an optional `observationId`, `sessionId` or `datasetRunId`; none or more than one is a 400). New `Catalog.BodyGuidance(op)` in `internal/catalog/bodyguidance.go`; no other operation has any, and every reduction of a result for the size cap (#190) keeps it.
- The facts are recorded in `docs/research/langfuse.md` section 1.14, verified against the release specs and sources before they were coded.

## Decisions & deviations
- **Version gate on the scores guidance.** The union catalog keeps the newest release's body schema for every deployment (generator: last spec wins, no per-release range for body properties). The release specs show `scores_create` requires `traceId` and has no `sessionId`/`datasetRunId` up to 3.52.0, `sessionId` from 3.53.0, `datasetRunId` from 3.55.0. To keep the text true for the connected deployment (triage note), `scoreTargets` names a target only when the body schema has it and the deployment's version has it (`Operation.deployment`; unknown version = newest). Three texts result: trace only (before 3.53.0), trace or session (3.53.0 to 3.54.x), all three. The first review round had a single gate at 3.55.0 and no text below it; the Spec reviewer called that partial, and sources at v3.53.0/v3.54.1 showed the rule exists there with two targets, so the tiers replaced it.
- **Index text format** `(execute_write, METHOD, destructive|not destructive)`; read lines keep `(execute_read)`. `method` and `destructive` are optional output members (present only on a write line), not conditional-`required`.
- **Excluded operations keep today's answer** in `execute_read` (`operation_not_found`, "not exposed by this server..."), as the ticket allows ("the answer they get today or `operation_not_found`").
- **Static tool texts name no write operation.** The Spec reviewer found that my first `describeOperationDescription` and `body.guidance` schema text named `comments_create` and `scores_create`; the tool list is the same in read-only mode, so that revealed the write operations. Both texts are generic now and `TestTheToolListWhileWritesAreOffNamesNoWriteOperation` walks every write ID.
- **Comment `projectId`**: the route stores the comment under the key's project whatever the body holds (v3.80.0, v3.225.11, v4.46.0, main); the guidance says only that it is the key's project and that `projects_get` returns it. Source of 3.0.0 to 3.79.x not read (recorded in section 1.14).
- The user skill (`skills/langfuse-api-mcp/references/errors.md`) still says `invalid_argument` is the answer to a write sent to `execute_read`, with a branch "if `execute_write` is not among your tools": true only in write mode now, where the tool exists, so the branch is dead but harmless. Left untouched on purpose (the ticket's doc list does not include the skill; `scripts/check-skill.py` passes).

## Learnings
- The Bash tool expands a backslash-u escape in a heredoc into the real character; gosec G116/staticcheck ST1018 then fail. Patch the file with Python using `chr(92)` and `grep -P` it afterwards (same as #178).
- A Python `str.replace` with a tab-indented block silently needs exact tabs; assert `count == 1` before replacing, or use Edit.
- `go test -race ./internal/server/` needs the chunked run (see #190, #201): `-test.list '.*'`, round-robin chunks, `GOGC=50 -test.parallel 6`.
- The first review found a leak a seam test did not cover: the tool list is mode-independent text; add a "names no write operation" check whenever static tool text changes.
