## What was built
- `.github/workflows/ci.yml` has a new Linux-only job, `generator`. On every push and pull request it checks out the repo with a SHA-pinned action, creates a venv, installs `pyyaml==6.0.3`, and runs `scripts/test_gen_union_catalog.py`.
- The job never regenerates the catalog. PR CI stays offline, except for the pip install (ADR-0012).
- A PR that breaks the generator's hostile-spec refusals now turns CI red. Those refusals are: cyclic, malformed or foreign `$ref`, and a non-JSON body.
- Spec #68 Testing Decisions was corrected on GitHub. "Not tested automatically: the generator script" became a "Generator script" bullet that says the unit tests run on every PR.
- Docs were synced: the README catalog paragraph, the `union-catalog.yml` header, the test script's WHEN header, and ROADMAP M3.

## Acceptance criteria
- [x] `ci.yml` runs `scripts/test_gen_union_catalog.py` on pull requests. This is job `generator`, and `actionlint` v1.7.7 is clean on it. Mutation proof: dropping `ref in seen` from `deref` in `scripts/gen-union-catalog.py` made the script exit 1, with `ERROR: test_a_recursive_schema_stops_generation`. - [ ] The green CI run on the pushed M3 branch is a human step after push, done in the same pass as #85. It cannot be done from a worktree that never pushes.
- Prompt injection and dangerous parameters: no tool, operation or parameter changed. All 5 hostile-spec tests are still in the script.

## Decisions & deviations
- The job has no `actions/setup-python`. It uses the runner's `python3`, as the weekly job does, and adds no further pinned action.
- The job runs on push too, because it inherits the workflow triggers. That is harmless, and it adds no path filter (option 2 was out of scope).
- The PyYAML install step is copied rather than shared. The ticket asked for the same pin in `ci.yml`. A shared requirements file with Dependabot `pip` coverage is follow-up #92.
