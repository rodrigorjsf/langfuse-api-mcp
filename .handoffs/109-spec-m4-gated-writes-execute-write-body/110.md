## What was built
- `LANGFUSE_MCP_ALLOW_WRITES` (exactly `true`/`false`, environment or config file, environment wins) turns write mode on; the startup log line `write mode` shows `on` and `source`.
- In write mode `execute_write` is registered (readOnly false, destructive true, idempotent false, openWorld true; declarative description). It takes `operationId`, `parameters` and `body`.
- A POST (e.g. `scores_create`) goes out with `Content-Type: application/json` and the compacted body; the answer comes back in the untrusted-data envelope (an empty 2xx answer is `data: null`).
- Every DELETE/PUT/PATCH is refused with `confirmation_unavailable` (static hint) before its arguments are even checked; nothing is sent.
- Body gate: object where the schema expects one, 256 KiB compacted, 32 levels, no body where none is taken, required body present; refusals never echo the value.
- Writes are never retried; their failure hints say so. Audit line at `Warn` with `confirmation` (`not_required` / `unavailable`).
- Four operations excluded (ADR-0004 amendment); credential-property catalog test.

## Decisions & deviations
- Caps chosen: body 256 KiB (compacted) and 32 levels (object/array depth, body = level 1). Exported as `catalog.MaxBodyBytes` / `MaxBodyDepth`.
- `LANGFUSE_MCP_ALLOW_WRITES` accepts exactly lowercase `true`/`false` (`TRUE`, `1` refused), stricter than the ParseBool used by the CA flag.
- Destructive refusal runs right after the operation lookup, before param/body checks (unconditional refusal per ticket AC). Spec's handler order (params, body, confirmation) is for slice 3 to restore.
- Audit `confirmation` values: `not_required`, and `unavailable` for a refused destructive call (not in the spec's list accepted/declined/not_required; slice 3 replaces it). Every `execute_write` line is Warn; `confirmation` is absent when the operation is unknown/invalid.
- `CheckBody` also refuses a missing required body and malformed JSON; body is sent compacted (semantically equal to what the agent sent).
- `langfuse.Client.Do` gained a trailing `body json.RawMessage` parameter; an empty 2xx body is accepted for non-GET methods only (reads unchanged).
- Failed-write hints (5xx, 429, network, timeout, internal) say the write was not retried and may or may not have been applied; codes/retryable flags unchanged.
- `writes_disabled` row in `errors.md` rewritten to match code (no such code exists; the tool is simply absent).
- Live write test runs only when `LANGFUSE_TEST_DEPLOYMENT` is set (pinned self-hosted), never on Cloud; cleanup deletes the score through a direct HTTP call because DELETE is refused in this slice.
- ROADMAP M4 marked in progress.
