# Security (non-negotiable)

Full risk→control mapping with sources: `docs/research/security.md`. Cite OWASP IDs **with the year** (IDs were renumbered: Excessive Agency = LLM06:2025 = LLM03:2026). Run `/security-review` before merging anything touching the areas below. Path-scoped parts load with their files: redaction (`security-redaction.md`), write gating (`security-writes.md`), requests to Langfuse (`security-requests.md`), tool results and discovery (`security-results.md`), supply chain (`security-supply-chain.md`), user skill and risk mapping (`security-checks.md`). Each line below is the invariant; the named file holds the full rule, which stays authoritative.

**Credentials**
- Langfuse keys come only from the server's environment/config — never from tool arguments, never forwarded from the MCP client (no token passthrough). Langfuse keys cannot be read-only, so the server is the only write gate for calls through the server; keys in the agent's own environment bypass it (#146).
- The config file (ADR-0011) must never hold keys: reject `LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY` found there (any spelling, after `export` and any blanks, #156) with a startup error; tests prove it.
- An unknown config-file key only draws a startup warning naming file, line and key (escaped, cut to 64 runes), never its value (#26); tests prove it.
- Redact `Authorization`, `sk-lf-…`, `pk-lf-…`, the HTTP bearer token and proxy credentials (`user:password@` in a proxy URL; used only for Basic proxy auth, logged as `scheme://host:port`) from logs, errors, hints, the audit line and tool output. A startup error for an invalid proxy value names the variable and its source, never the value.
- Langfuse keys (`pk-lf-…`/`sk-lf-…`) are redacted where a key starts: at a word boundary, after a JSON escape written as text, after a place the cleaning removed something, and a generated key (prefix + UUID) wherever it stands; the exact rule, its accepted over-redactions and the cases left: `security-redaction.md`.
- Header credentials inside Langfuse data keep their scheme and lose their token to `[REDACTED]`, before any cut, for the forms the rule names (a header or `Bearer` line, an `Authorization` member of a JSON object, the quoted text form); it does not cover every form (a token under 16 characters, a value with no scheme, a name/value pair map, cookies and API-key headers stay), so never promise more; the full rule and the cases left: `security-redaction.md`.
- After startup the key pair travels only as `langfuse.KeyPair`, which renders `[REDACTED]` in fmt, JSON and slog; never copy the keys into plain `string` fields.

**Write gating** (ADR-0003 and its amendment)
- `execute_read` accepts GET operation IDs only. `execute_write` is not registered unless `LANGFUSE_MCP_ALLOW_WRITES=true` (exactly `true`/`false`, environment or config file, environment wins; any other value stops startup naming the variable and its source, never the value). Tests must prove both.
- The tool set is fixed at startup; it never changes per request or per client.
- While write mode is off no tool tells a write operation ID from one that is in no release (#192): `execute_read` and `describe_operation` answer it `operation_not_found` in the words and with the hint of an unknown ID, naming no HTTP method, echoed only redacted, stripped, quoted and cut to 64 bytes, and sending nothing. In write mode `execute_read` keeps `invalid_argument`, naming the method and pointing to `execute_write`. An excluded operation keeps its answer. The tool descriptions and schemas are the same in both modes, so they name no write operation ID. Tests prove each, with every write operation of the catalog walked.
- `execute_write` refuses an excluded, unknown or read operation ID, checks parameters like `execute_read` and the body (size, depth, top-level shape, then the deployment version's JSON Schema) before any request, and runs a destructive operation (DELETE, PUT, PATCH) only after the user confirms that exact call through form elicitation with an HMAC-signed state, fail-closed; no setting skips the confirmation; POST creates run without one, and replay of the identical confirmed call within the expiry is not prevented; a write is never retried; the ADR-0004 operations stay excluded from the catalog; the full rule: `security-writes.md`.

**Every slice: prompt injection + dangerous parameters** (LLM01:2025/2026, MCP05/MCP06:2025)
- Any spec, ticket or change that adds or alters a tool, operation, parameter, workflow, or write path lists in its acceptance criteria (a) its prompt-injection cases — instructions, hidden/bidi characters and markup inside Langfuse payloads, echoed input in error text — and (b) its dangerous-parameter cases — unknown params, URLs/schemes/hosts, traversal, control characters, wrong types, out-of-range limits, oversized filters or query JSON.
- Each case is proven by a test at the seam. A missing case is a Spec-axis finding in `/code-review`; a case that cannot be closed now becomes a `/follow-up-issue`, never a silent gap.

**Requests to Langfuse** (SSRF / injection)
- Base URL comes only from operator config; `https` required except loopback hosts.
- Model input selects only an operation ID and parameters: every value is checked against the operation schema before any request (what stays Langfuse's to check: `orderBy`, the grammar of a filter condition, the value of `fields`), unknown parameters are refused, path parameters refuse URLs, schemes, hosts, `//`, `.`/`..` segments, `/` and `\` (Folder names only on a closed allow-list) and are percent-encoded, a control or invisible character in a value is refused, never removed, and a JSON filter is decoded, checked and re-encoded; no refusal holds the value; the full rule: `security-requests.md`.
- Custom `CheckRedirect`: refuse any redirect that changes scheme, host, or port (Go forwards `Authorization` on same-host and subdomain redirects).
- Served parameters (#173, ADR-0012 amendment): an operation offers, and `execute_read`/`execute_write` accept, only the parameters the deployment's version serves; the catalog resolves them at startup from each parameter's `x-introduced`/`x-removed`, and with no detected version serves the newest release's, which the startup log says. A parameter of the operation that the version does not serve is refused with `invalid_argument` before any request: the message names the parameter (a catalog name, never the caller's text), the operation, the deployment's plain version and the release range from the catalog, never the value; the hint is static text and names only the way of paging the operation has, `page`, `cursor` from `meta.cursor` or neither, from its served parameters (#193). A name that is no parameter of the operation in any release keeps the unknown-parameter refusal, the name echoed only redacted and cut to 64 bytes; a served parameter's value gets every check below. Tests prove it at the catalog seam (both executors share `Operation.Request` and `parametersHintFor`) and at the `execute_read` seam; no write operation carries a ranged parameter today, so `execute_write` has no test of its own for it.
- Filter scan: on a version that does not serve one of the two filters on the closed list `catalog.ScannedFilters`, `execute_read` scans at most `MaxScanPages` pages and filters the rows itself, checked as if the filter were served; the full rule: `security-requests.md`.
- Timeouts, one shared rate limit and concurrency cap, max response bytes, the result size cap (clip values, then drop rows, never a cursor), list `limit` and metrics `row_limit` bounds. The limits are set only by the operator (`LANGFUSE_MCP_RATE_LIMIT`, `LANGFUSE_MCP_MAX_CONCURRENCY`, `LANGFUSE_MCP_MAX_RESULT_BYTES` within 16384 to 1048576), never by a tool argument, and an invalid value stops startup naming the variable and its source, never the value. Every hint is static text naming only the ways the operation has, never a value. The full rule: `security-requests.md`.

**Tool results** (LLM01:2025/2026, MCP06:2025)
- Langfuse payloads are untrusted data: wrapped in a labelled envelope, stripped of invisible, bidi and control characters (a terminal escape sequence whole), JSON text inside a string decoded and cleaned down to four levels, never rendered and never echoed unescaped into error text. A proxy's CONNECT answer is dropped, never echoed. A continuation cursor is opaque: never decoded, handed back only as `data.meta.cursor` inside the envelope, never in a hint or the audit line. The full rule: `security-results.md`.
- Tool names/descriptions are static strings compiled into the binary — never built from API data.
- Discovery (`search_operations`, `describe_operation`) and `get_trace_tree`: catalog text is cleaned at load and framed as third-party data; `query` and `operationId` over 128 runes or holding a control or invisible character are refused, the query is never echoed, and an unknown operation ID or argument name is echoed only redacted, stripped and cut to 64 bytes; notes and guidance are static text decided by the catalog and the deployment profile at startup, never by a payload or a client, and a hint may depend on the call only as the full rule says (the trace reads hint on the word `trace`); results fit the result size cap; `get_trace_tree` refuses bad input before any request. The full rule: `security-results.md`.

**Build metadata** (#127): the server version in `initialize` and the startup log is the linker-injected one, else the build info's module version only when it is a release tag (`vX.Y.Z` or `vX.Y.Z-pre`, no pseudo-version, no build metadata such as `+dirty`), reported without the `v`; anything else is `0.0.0-dev`, so no other build-metadata string is echoed; tests prove it.

**Transport**
- stdio: logs to stderr only. It offers no protocol from 2026-07-28 (#145), and it reads no byte of stdin until the session has recorded that (#191): go-sdk v1.8.0 starts reading inside `Server.Connect` and records the transport's protocols a few instructions later, so a `server/discover` probe already waiting in the pipe, as Claude Code leaves it during a slow startup, could be answered with 2026-07-28 and stored as the session's `initialize` parameters, and the legacy `initialize` after it refused as a duplicate. A probe therefore never negotiates a session, however early it arrives, and is answered with the older protocols only; a session is negotiated only through the legacy `initialize`; neither the client capabilities of a handshake, nor a probe sent before, between or after the `initialize` messages, nor a second `initialize` change the tool set or the write gate, and a malformed `server/discover` is refused without dropping the connection; tests prove it, with the probe forced to be handled inside the SDK's window. Both workarounds go once go-sdk accepts a legacy `initialize` after a probe and records a transport's protocols before it reads the first message (#162). HTTP (opt-in, **Planned**, #160; stdio is the only transport today): bind 127.0.0.1, require a random ≥256-bit bearer token compared in constant time, validate `Origin` (403 on invalid) and `Host` (loopback only), answer session GET/DELETE with 405.

**TLS** (ADR-0006): system pool + explicit/ambient CAs appended in code; `SSL_CERT_FILE`/`SSL_CERT_DIR` are captured and removed from the environment before anything loads certificates (proven by `TestExecutableTrustsTheOSStoreAndAmbientCAsAtOnce`); `MinVersion` TLS 1.2; no skip-verify option exists.

**Audit**: one structured stderr log line per tool call (tool, operationId, method, status, latency, bytes, requests: the Langfuse requests the call made) — metadata only, never payloads, and the cause of a request that got no answer never holds the request URL or a refused redirect's target (#156); an `execute_write` line is at `Warn` and adds `confirmation` (`not_required`, `requested`, `accepted`, `declined`, `unavailable`, `invalid`).
