## What was built
The union catalog generator (`scripts/gen-union-catalog.py`) now keeps each write operation's JSON request body, with `$ref`s inlined from the same release spec the operation was taken from. A cyclic, malformed or foreign `$ref`, or a body that is not a single `application/json` schema, stops generation with a message naming the ref or operation. The regenerated catalog has `requestBody` on 49 operations, reproducible byte for byte. The catalog exposes it as `Operation.Body *RequestBody{Required bool; Schema json.RawMessage}`. Every string in the schema is cleaned of hidden characters at load: keys by `visible`, values by `visibleText`, which keeps tab and line breaks. Nothing reads it yet; it is for the M4 body gate. Read paths are unchanged.

## Decisions & deviations
- **Cycles fail loudly instead of being cut at a fixed depth.** The ticket contradicts itself ("cut at a fixed depth" vs. "cyclic $ref fails generation loudly"). No request body in any spec from v3.0.0 to v4.46.0 is recursive (measured over all 116 distinct specs). A loud failure never emits a partial schema. Risk: the first recursive upstream body breaks the weekly regeneration, which is when to revisit.
- **Option 1 (inline)** was chosen over option 2 (per-operation components). Inlining roughly quadruples the size, but it stays at 0.46 MiB, well under budget.
- **Generator tests contradict spec #68's "generator not tested automatically".** The ticket's AC asks for a test. The tests run in the weekly workflow before regeneration. PR CI does not run them yet: #89.
- **Every string is cleaned, not only descriptions.** Keys, enum values and titles are cleaned too. A key collision after cleaning fails the load, so the result never depends on map order. This changes an enum or key only when it holds hidden characters, which would itself be hostile.
- The ingestion body (an excluded operation, about 66 KB) is still emitted. The generator does not know the ADR-0004 exclusions, and Go drops the operation.
- Headers, responses and non-JSON bodies are not kept. None exist today; a non-JSON body fails generation.

## Notes for dependent tickets

Strings are cleaned; tab and line breaks are kept. The schema is third-party text: link reduction and length cuts apply only to index lines, so apply them if the schema is ever shown to the agent.
