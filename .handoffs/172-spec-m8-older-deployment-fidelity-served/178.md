## What was built
`describe_operation` now tells an agent three things it used to learn from a failed call. `prompts_get` `label` and `version` say that with neither the version labelled `production` is returned, which may not be the newest, that the label `latest` names the newest, and that the two are not sent together. `trace_list` `fields` lists its values (`core` always, `io`, `scores`, `observations`, `metrics`) and what a left-out group looks like, and only on a deployment whose version serves `fields` (from 3.73.0). `legacy_metricsV1_metrics` `query` has the same key list as `metrics_metrics` (the validator's own) and the v1 shapes, with a worked example, the number of traces per name. The 404 of `prompts_get` called with no label and no version adds a static sentence naming the implicit `production` label and `latest`; it never holds the prompt name.

## Decisions & deviations
- Guidance is now a table, `staticGuidance` keyed by `(operation, query parameter)`, instead of a growing `switch` (seven cases would have repeated `p.In == "query" && p.Name == …`). `isMetricsV2Query` and `Operation.HasGuidance` were removed: the first existed only to leave the legacy operation out, the second only chose between two wordings of the metrics hint, a branch both metrics operations made dead (`metricsQueryHint` now always says `describe_operation` returns the query's shape and a worked example).
- The two metrics guidances come from one builder (`metricsGuide.text`); the v2 text is byte-identical to before (the existing literal test passes unchanged).
- Source of the facts, checked with the `langfuse-docs` MCP on 2026-10-10: `fields` values and the empty-group behaviour from the API reference of `GET /api/public/traces`; the five views, the aggregations, the `orderBy` sample and the example of the legacy query from `GET /api/public/metrics` and the metrics API page. The legacy `orderBy` sample is the documented `{"field":"name","direction":"asc"}`, not `{aggregation}_{measure}`: that form is documented for v2 and is unverified for v1 (campaign M5 saw one `orderBy` give a Langfuse 400).
- "Send label or version, not both" is added to the prompts guidance (`docs/research/langfuse.md` section 4.2: both together return 400); it was not in the ticket text, and it is one clause.
- The `production` sentence is appended after the Folder-name hint, so a Folder-name 404 with no label carries both; it is not added to a 404 that means `operation_unavailable`, or to a 400.
- `ImpliesProductionLabel(Request)` lives in `catalog` (placement table: parameter knowledge) and reads the sent query: a `null` label (omitted) still counts as no label.
- Not done, on purpose: `trace_get` `fields` and the `fields` of five other operations get no guidance (the ticket says "No other parameter gains guidance"), and the truncation hint still names `fields` without values; see Follow-up issues.

## Learnings
- The Bash tool expands a backslash-u escape in pasted source into the real character, so a Go test string with `U+202E` lands as a hidden character and gosec G116/staticcheck ST1018 fail; write escapes through a Python script using `chr(92) + "u"` plus the hex digits and `grep -P` the file afterwards.
- `gofmt` is not on the bash PATH; run `$(go env GOROOT)/bin/gofmt`.
- A `sed` mutation silently does nothing after `gofmt` realigned a map literal; confirm the mutated file differs before trusting a "green" mutation check.
- `ticket-reviewer` agents return findings as a message to the caller, not as the final text.
